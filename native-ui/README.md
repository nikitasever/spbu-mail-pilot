# Native Android — Kotlin + Jetpack Compose

Разработческая сборка, первый рабочий сценарий: входящие и чтение поверх
существующего Java-кода. Это начало перехода, не замена всех функций клиента.
План Android и локальной версии ПК: [native-and-desktop.md](../docs/migration/native-and-desktop.md).

Требуются JDK 17+, Android SDK 34, Build-Tools 35.0.0 и закреплённый Gradle 8.9 (wrapper включён).
Из корня репозитория:

```sh
python -c "import build; build.dependencies()"
cd native-ui
./gradlew :app:assembleDebug
```

`ANDROID_HOME` указывает на SDK. Старые assets включаются локально из корня;
при изменении их исходников сначала выполните прежнюю сборку UI.
Ключи и production signing не добавляются. Не устанавливайте debug APK поверх
рабочего приложения: applicationId тот же, и Android требует прежний сертификат.
Перед испытанием на устройстве нужна отдельная согласованная тестовая установка
или сборка с существующей подписью; удаление рабочего клиента теряет его данные.

Gradle использует production manifest как источник и генерирует его копию с
дополнительным launcher «Почта · Compose». Production manifest не меняется.
Контракт текущего шага: чтение без изменения прочтения и без записи общей
офлайн-копии; страницы по 50 заголовков через «Показать ещё». Вложения открываются из Compose: PDF/DOCX
в прежних встроенных просмотрщиках, остальные форматы через Android с временным
разрешением только на чтение. Нужна сеть для загрузки файла.
«Ответить» открывает нативный редактор Compose с Reply-To, In-Reply-To и References.
«Написать» открывает новый или сохранённый нативный черновик. Поддержаны Кому,
Копия, Скрытая копия, тема, текст и автоматическая подпись из настроек аккаунта.
На этом шаге доступен один нативный черновик на ящик; старые WebView-черновики и
очередь отправки не изменяются. Новый ответ не затирает существующий черновик.
Черновик шифруется AES-GCM ключом Android Keystore в account-bound AtomicFile.
Статус «Сохранено» появляется после записи. После ошибки сохранения Back не
закрывает редактор; после пересоздания Activity текст остаётся в ViewModel.
После уничтожения процесса сохранённый черновик открывается с диска; Bundle
хранит только ключ аккаунта, без текста письма и пароля.

Отправка запускается только кнопкой, после проверки адресов и десятисекундного
интервала отмены. Уход в фон отменяет ожидание. Уже начатый SMTP не выдаётся за
отменённый: результат фиксируется даже после закрытия Activity. Перед SMTP
сохраняется маркер dispatching. Если результат неизвестен или процесс уничтожен,
повтор блокируется; разрешить его можно только отдельно, после проверки и
подтверждения. Отказ записи результата оставляет тот же безопасный маркер.
Ошибка копирования в «Отправленные» не превращает отправленное письмо в повтор.
Версия записи защищает от перезаписи/дублирования из второго экземпляра Activity.

Кнопка «Прикрепить файл» сохраняет текст до открытия Android OpenMultipleDocuments.
Выбранные content-URI копируются через прежний AttachmentFiles: до 10 файлов по
100 МиБ, ограничение проверяется по реально прочитанным байтам даже без SIZE.
Копии лежат в закрытой папке files/native-attachments/<account>/<draft-id>;
метаданные — в зашифрованном черновике. Сами файлы не шифруются отдельным ключом
приложения: используется закрытое Android-хранилище, как у прежних outgoing uploads.
Копии не зависят от дальнейшего доступа к URI. Постоянные URI-разрешения не берутся.

Добавление пачки целиком фиксируется после успешного копирования всех файлов;
ошибка или отмена убирает новые незавершённые копии. При потере результата picker
после уничтожения процесса нужно выбрать файлы заново; текст остаётся на диске.
Уход в фон во время копирования запрашивает отмену; если провайдер заблокировал
чтение, отмена завершится после возврата из него. Удаление файла сначала сохраняет
метаданные без него и затем удаляет копию. После подтверждённого SMTP-успеха копии
очищаются по «Готово»; при неизвестном результате сохраняются для проверки.
Повторный запуск приложения не отправляет файлы автоматически.

Подсказки получателей работают в Кому/Копии/Скрытой копии: поиск от двух символов,
debounce 300 мс, до 20 результатов. Локальные contacts/phoneContacts/recipientBook
активного аккаунта читаются отдельно от сетевого worker, чтобы медленный справочник
не задерживал локальные совпадения. UniversityDirectory используется только для
mail.spbu.ru и уважает прежние разрешённые адресные книги; для других аккаунтов
остаётся локальный поиск и ручной ввод. Источник виден под каждым адресом.

IME composition/выделение или курсор в середине строки не запускают поиск. Выбор
заменяет только конечный фрагмент, сохраняет предыдущие адреса, учитывает кавычки
и комментарии, исключает дубли во всех трёх полях. Результат проходит прежний
OutgoingMail-парсер и сохраняется обычным механизмом черновика. Никакого SMTP
по выбору подсказки нет. Смена поля/ввода/черновика/аккаунта, фон и отправка
инвалидируют результат поиска. Данные поисков не записываются на диск; HTTP уже
начатого справочного запроса не прерывается принудительно, но поздний ответ не
показывается. При сбое сети локальные результаты остаются, доступен повтор.

В Compose добавлены «Шаблоны» и ручная «Подпись». Шаблоны активного аккаунта
читаются из существующего state без записи поверх WebView-настроек. Шторка
показывает название/превью и явную вставку; доступны загрузка, пустое состояние,
ошибка и повтор. Создание/изменение/удаление шаблонов и настройка подписи пока
остаются в прежнем клиенте; нативный редактор использует уже сохранённые значения.

Текст шаблона вставляется в курсор или заменяет выделение с теми же абзацными
отступами, что в прежнем редакторе. Выделение хранится в ViewModel; программная
вставка возвращает курсор/фокус в конец вставленного фрагмента. UTF-16-пары не
разрезаются, лимит 100 000 символов проверяется до изменения. Пока IME-ввод не
завершён, кнопка не выполняет вставку. Ручная подпись добавляется в конец даже
при выключенной автоматической подписи, но уже имеющийся конечный блок (включая
пустые строки после него) не дублируется. Старые черновики автоматически не
переписываются при смене подписи. Вставка сначала сохраняется в зашифрованный
черновик, затем показывается; ошибка записи оставляет прежний текст в редакторе.
Фон закрывает шторку и инвалидирует позднюю загрузку. Эти действия не запускают SMTP.

Отправка по расписанию в Compose ещё не перенесена; для неё остаётся прежний клиент. Просмотр входящих
вложений уже работает. Возврат из просмотрщика не сбрасывает открытое письмо.
Список и чтение перенесены в NativeInboxModel (AndroidViewModel + SavedStateHandle).
Поворот/смена конфигурации сохраняют строки, открытый текст и выполняющийся запрос
в памяти ViewModel. Позиции списка и текста сохраняются с проверкой аккаунта и
точного ключа письма. Возврат из редактора/просмотрщика не запускает повторную
загрузку. SavedStateHandle содержит хэш аккаунта, папку, UIDVALIDITY/UID и числовые
позиции — без текста, имён, адресов и паролей. После уничтожения процесса список
и письмо восстанавливаются из прежнего офлайн-кэша; если текста нет, доступна
явная кнопка загрузки. Навигация проверяется тем же MailNoticeTarget, что в ссылках
на письмо. При смене аккаунта прежняя навигация и строки сбрасываются.

Фоновый выход/смена письма/обновление инвалидируют поколение запроса. Активный
MailReader закрывается в отдельном executor; устаревший ответ не публикуется даже
если блокирующий JavaMail ещё не завершился. Close — best effort: он может ждать
внутреннюю блокировку JavaMail/сетевой таймаут, мгновенный обрыв сокета не обещается.
При обычном уходе в фон отменённое чтение не перезапускается автоматически.
Полученный файл выдаётся просмотрщику однократно и только после возвращения и
разблокировки; при отмене временный файл удаляется.

Пагинация сохраняет строки и позицию при добавлении страницы. Онлайн-курсор
использует тот же MailReader/UID-снимок, что первая страница; чтение письма и
вложений использует отдельные соединения и не сбивает курсор. Курсор офлайн-копии
отделён от источника текста выбранного письма. NativeMailPage проверяет папку,
UIDVALIDITY, snapshot, total и продвижение nextOffset; дубликаты подавляются.
Пустая из-за удалённых UID страница всё равно продвигает курсор. При ошибке строки
остаются, продолжение требует явного обновления. Поворот сохраняет соединение;
обычный фон закрывает онлайн-курсор и предлагает обновить список перед продолжением.
После смерти процесса восстанавливается доступная офлайн-копия, а не прежний
онлайн-снимок со всеми загруженными страницами. Никаких фоновых IMAP-загрузок для
восстановления старой глубины списка не запускается.
При отсутствии входа используйте «Все возможности почты». Compose использует
активный сохранённый аккаунт; смена ящика блокирует отправку старого черновика.

Проверки политики черновика и отправки без сети:

```sh
./native-ui/test-compose.sh
```

Они компилируют актуальные Java-исходники, проверяют заголовки настоящего MIME,
изоляцию аккаунтов, устаревшую ревизию, отказ диска до/после SMTP и неопределённый
результат. NativeAttachmentsTest сериализует и разбирает настоящий MIME с файлом,
проверяет байты, имя, лимиты, отмену/обрыв потока и изоляцию папок. Это не тест
Android-проводника, Keystore, клавиатуры или жизненного цикла устройства.
NativeReadGateTest проверяет поколения, поздний attach/detach и закрытие соединения
вне вызывающего потока, включая блокирующий close; реальный JavaMail-сокет не
используется. MailNoticeTargetTest проверяет безопасное восстановление ключа.

Проверено в этой рабочей среде: `:app:assembleDebug` завершился успешно.
Проверены подпись debug APK, наличие Compose и классов старого движка,
новая точка входа только в сгенерированном manifest и совпадение включённых assets.
На устройстве или эмуляторе новый экран ещё не проверялся. Рабочий APK не опубликован
и не заменён. Версии Kotlin 2.0.21, Compose BOM 2024.09.03, AGP 8.7.3 закреплены
как совместимый стартовый набор; это не заявление о последних версиях библиотек.

NativeMailPageTest проверяет 50/50/25 страниц, порядок, дубликаты, удалённые UID,
несовместимые курсоры и ревизию офлайн-копии без сетевых соединений.

NativeRecipientsTest проверяет Unicode-совпадения, дубли/некорректные адреса,
кавычки/комментарии в префиксе, IME/caret guard и привязку результатов к запросу.
UniversityDirectoryTest и DirectoryAutocompleteTest используют фиктивный транспорт
для проверки прежнего серверного контракта; реальный справочник и IME устройства
не проверялись.

NativeWritingToolsTest проверяет валидные/повреждённые шаблоны и лимит100, вставку
в курсор/выделение, абзацы, UTF-16, ограничение тела, конечную подпись без дублей,
восстановление текста из DTO и настоящий text/plain MIME. Focus/IME/шторка на
устройстве ещё не проверены.

В чтении добавлена кнопка «Ответить всем». Новый черновик получает полный Reply-To
(или From при его отсутствии), затем исходные To и Cc. Текущие login.from/login.user
и повторы без учёта регистра исключаются; дополнительные алиасы автоматически не
определяются. Если остались только Cc, первый адрес переносится в To. Скрытые копии
и входящие вложения не добавляются. Тема и RFC-связь с исходной веткой сохраняются.
Адреса видны и редактируются до обычной явной отправки с интервалом отмены.

Неполные старые офлайн-заголовки, группы, некорректный адрес или превышение лимита
не приводят к молчаливому сокращению списка. Редактор объясняет отказ; можно
вернуться и явно нажать «Обновить письмо» либо ответить одному отправителю.
Обновление читает BODY.PEEK с сервера, не пишет общий кэш и сохраняет старый текст
при ошибке. Открытый ранее нативный черновик, даже с ревизией0, возобновляется с
заметным сообщением вместо создания/перезаписи нового ответа.

NativeReplyTest проверяет несколько Reply-To, To/Cc, исключение себя/дублей,
отсутствие Bcc/вложений, лимиты и отказ при неполных заголовках, восстановление
черновика и настоящий MIME с In-Reply-To/References. Фиктивный MailReader проверяет
новое поле replyToRecipients и сохранение Seen=false; ReadFlagTest повторно проверяет
прежние явные изменения флага. Реальный сервер и Android-кнопки требуют устройства.

Меню «Другие действия письма» в доке чтения содержит «Переслать текст». Получатель
остаётся пустым; тема получает Fwd: без повторного FW:/Fwd:. В тело добавляются
отправитель, дата, исходная тема и точный загруженный текст. Автоподпись использует
прежнюю настройку аккаунта. Исходные To/Cc/Bcc, Reply-To, Message-ID, References,
UID/папка и вложения не переносятся в новый конверт. Собственный Message-ID отправки
создаёт прежний MIME-движок. Вложения можно добавить обычным системным picker.

Сохранённый kind=forward-text восстанавливает название редактора и постоянное
пояснение об отсутствии автоматического переноса вложений, даже после изменения
полей или перезапуска. Существующий нативный черновик возобновляется вместо
перезаписи. Пустой/помеченный как частичный текст или превышение лимита с учётом
заголовка и подписи останавливают подготовку; текст не усекается. Известный маркер
«[Показана часть текста]» считается консервативным признаком неполной загрузки.
Для полной пересылки исходного EML/вложений пока нужен прежний клиент.

NativeForwardTest проверяет отсутствие унаследованных получателей/скрытых копий,
заголовков ветки и вложений, неизменность исходного текста/emoji, границы100000,
отказ при неполной загрузке, восстановление признака пересылки и сериализованный
text/plain MIME с вручную выбранным адресатом. Сеть не используется; Android-меню,
масштабирование и клавиатура на устройстве ещё не проверены.

В шапке редактора есть «Удалить» с подтверждением «Удалить черновик». Закрытие
диалога, системный Назад и уход в фон не подтверждают удаление. Пока диалог открыт,
редактирование, отправка и выбор файлов заблокированы. Удалять можно только
editing-запись: countdown сначала отменяется пользователем, а dispatching/uncertain
сначала требуют прежней проверки результата доставки. Серверные/WebView-черновики
и очередь расписания этим действием не затрагиваются.

Перед удалением повторно проверяются foreground/AppLock, активный аккаунт и точные
owner/id/revision/status на диске под общим NativeDraftStore.gate. Более новая
версия другого окна не удаляется. Метаданные удаляются первыми, включая остатки
AtomicFile .bak/.new; только после подтверждённого удаления очищаются mail-* копии
этого draft-id. Другие аккаунты/черновики и чужие цели symlink не очищаются. Ошибка
метаданных оставляет текст в редакторе и не запускает очистку файлов; повторная
автозапись не может воскресить уже удалённую запись. Ошибка очистки после удаления
не восстанавливает черновик и показывается отдельным сообщением в чтении/списке.

Восстановление редактора после смерти процесса теперь работает в режиме restoreOnly:
отсутствующий черновик не превращается в новое пустое письмо. Явное «Написать»
продолжает создавать новое письмо. NativeDraftDiscardTest проверяет версии/статусы,
порядок удаления, отказы, настоящие временные папки/ссылки и отказ устаревшего save/
send после удаления. Android AtomicFile/Keystore и диалог требуют проверки устройства.

В меню открытого письма есть явное «Пометить прочитанным/непрочитанным». Используется
прежний MailReader.seen с точными folder/UIDVALIDITY/UID; подключение, активный ящик,
foreground/AppLock и поколение запроса проверяются перед записью. Ответ должен
содержать boolean seen, совпадающий с запрошенным значением. До подтверждения стиль
строки/письма не меняется; ошибка сообщает, что изменение могло примениться, и
предлагает явное обновление. Офлайн-очереди и автоматического повтора нет.

Подтверждённые значения и свежие онлайн-наблюдения хранятся в NativeSeenFlags в
памяти ViewModel с привязкой owner/folder/validity/uid. Старая страница пагинации или
кэшированное тело не откатывают стиль; явное обновление списка создаёт свежий снимок
и очищает прежние переопределения этой папки. Смена аккаунта очищает карту. Общая копия
OfflineMailStore не переписывается: после смерти процесса до обновления прежним
клиентом она может показывать старую отметку; серверный статус проверяется явным
обновлением. Просмотр тела и файла остаётся BODY.PEEK без изменения Seen.

Уход/навигация инвалидируют поздний результат, но best-effort close не гарантирует
отмену уже начатой команды IMAP. Запрос устанавливает конкретное значение флага,
не переключает неизвестное серверное состояние. NativeSeenFlagsTest проверяет
подтверждения/изоляцию/старые страницы и настоящий JavaMail с фиктивной папкой;
NativeReadGateTest и ReadFlagTest проверяют прежние границы. Устройство и реальный
сервер пока не проверены.

## Прямой рендер текущего интерфейса

```sh
./native-ui/render-preview.sh
```

Опциональный `-PrenderUi` подключает закреплённый Paparazzi1.3.5 и тестовые файлы
из app/src/previewTest/kotlin. Входящие, чтение и редактор строятся
Android Layoutlib непосредственно из NativeInbox/NativeComposer и InboxTheme.
В fixture явно установлены демонстрационные данные, модели не запускают resume,
запросы, хранилище или реальные обработчики отправки. Это не Android Activity на
телефоне: системные отступы/клавиатуру/AppLock/жизненный цикл следует проверить
отдельно. Показывается тёмная тема и обычный масштаб шрифта.

PNG находятся в app/src/test/snapshots/images, отчёт — в app/build/reports/paparazzi/debug.
Первые зависимости рендера загружаются отдельно. Они нужны для Gradle/tests,
не включаются в APK; обычная сборка не подключает previewTest-исходники.

Входящие теперь показывают декоративные инициалы, мягкий тон непрочитанных,
яркую точку и разделители от начала текста. «Есть вложения» выводится только при
hasAttachments=true; отсутствие метаданных не превращается в придуманное число
файлов. Текст/дата не накладываются на аватар, вся строка остаётся одной кнопкой.

Четвёртый рендер — настоящее NativeFolderList в тестовом контейнере. Layoutlib не
захватывает отдельное Android Dialog-окно, поэтому scrim/отступы/закрытие шторки
этим снимком не проверяются. Пустой снимок под Dialog не считается его проверкой.

## Папки в Compose

Заголовок текущей папки открывает шторку. Сначала доступны папки сохранённых писем;
«Загрузить папки с сервера» явно получает полный LIST через прежний MailReader.
Неоткрываемые контейнеры исключаются. INBOX стоит первым, другие фактические имена
и регистры сохраняются отдельно. Для системных имён есть перевод и исходное имя
второй строкой; «Черновики на сервере» отделены от NativeDraft. Серверные черновики
пока читаются как письма, их редактирование остаётся в прежнем клиенте.

Выбор из сохранённого списка читает кэш, из серверного — сервер. Отсутствующая
локальная папка не выдаётся за пустую на сервере: показано объяснение и обновление.
Смена папки сбрасывает строки/тело/позиции/курсор до запроса. Первая страница и
продолжение проверяются на folder, pager дополнительно содержит owner+folder.
Устаревшие onClick/scroll-callback другой папки не применяются. В SavedStateHandle
folder/mailRoute принимаются только при совпадении owner; иначе используется INBOX.

У LIST отдельный generation/connection: закрытие шторки не сбрасывает курсор писем,
поздний ответ после закрытия/фона/смены аккаунта не публикуется. Выбор новой папки
закрывает прежний pager. Список не пишет общий кэш. Обновление одной папки очищает
Seen-переопределения только этой папки, сохраняя отметки других папок.
NativeFoldersTest проверяет имена/иерархию Unicode/регистры, порядок, отказ без
усечения неправильных и больших списков, восстановление аккаунта, первую страницу
чужой папки и JavaMail LIST с фиктивными контейнерами. Реальный IMAP/ACL, окно
шторки и поворот требуют устройства.

## Поиск, контакты и календарь

В Compose добавлены явный серверный/офлайн поиск почты, фильтры загруженных
результатов, отдельные контакты и просмотр календаря. Серверный поиск использует
прежний MailReader.page(query), BODY.PEEK не меняется. Контакты используют
UniversityDirectory.page (local/personal/team/company), полный буквенный индекс,
безопасную пагинацию и открывают существующий либо новый черновик без перезаписи.
CalendarBook даёт сохранённые/явно обновлённые месяцы, локальные события и активные
задачи добавляются из текущего account state. Режимы: день, неделя, месяц, повестка.
Изменение контактов и подключений календаря ещё не перенесены.

Остаток **всего** переноса и порядок работ фиксируются отдельно:
[native-feature-status.md](../docs/migration/native-feature-status.md).
Количество проверок: 18 host-наборов; 7 базовых Compose render-состояний. Реальная
сеть и устройство в этой среде не проверялись.

## Задачи и заметки

В меню «Ещё → Задачи и заметки» работают списки, локальный поиск, создание,
редактирование, выполнение/возврат задач и удаление с подтверждением. Приоритет,
срок и напоминание используют прежние поля и NoticeCenter; ссылки mail/calendarSource
сохраняются. Запись меняется по точному исходному record CAS в свежем account JSON,
без второй базы. Несохранённая форма живёт только в ViewModel, до уничтожения процесса.
SharedStateMerge защищает нативные изменения от устаревшего WebView; при конфликте
текст остаётся в форме. Сохранение только кнопкой, отмена изменений подтверждается.
19 host-наборов; два дополнительных render-состояния. Нового выпуска нет.

## Свои события

В календаре кнопка «Своё событие» открывает нативный редактор с выбранной датой.
У локальных карточек есть «Изменить своё событие». Save возвращает к сохранённой
дате, delete требует подтверждения. Серверные события остаются только для чтения.
Изменение/удаление атомарно обновляет существующие eventMailLinks, сохраняя mail refs,
другие события и задачи. Подробности: [local-events.md](../docs/migration/local-events.md).
Фокусированный запуск: `native-ui/test-local-events.sh`; необязательная проверка
чувствительности сравнения: `python native-ui/tests/event-canary.py` (нужен javac).

## Связанные письма

Из задачи открывается исходное письмо, из локального/серверного события — письма
существующих связей. Back возвращает в источник с прежним состоянием и прокруткой.
Почтовая папка/фильтр/поиск не подменяются. Точные owner/folder/UID/UIDVALIDITY;
битая/удалённая/чужая ссылка не ищется по похожей теме. Новые связи пока в прежнем UI.
Фокусированная проверка: `native-ui/test-mail-links.sh`. Ограничения process death и
устройства: [linked-navigation.md](../docs/migration/linked-navigation.md).

Событие из письма: тема/предложенная московская дата, явное сохранение event+link, повторное открытие без дубля, переход в календарь. В формах задач/событий — Material DatePicker и TimeInput. Ограничения: [mail-events.md](../docs/migration/mail-events.md).

Перенос из меню reader: архив, спам, корзина, существующая папка, подтверждение и защита связанных записей. [Подробности](../docs/migration/mail-moves.md). Текущие исходники новее последнего APK; пересборка APK отложена до окончания переноса по указанию пользователя.

Категории: редактор пяти правил/уведомлений, сводки, категории в почте и reader, фильтр загруженной выборки. Общий MailCategories/JSON, сохранение по record CAS. [Правила и проверки](../docs/migration/categories.md).

Метки и личные напоминания об ответе: меню reader, сроки по Москве, изменение/отмена, отдельный список с исходным письмом и бейджи; общий NoticeCenter. [Ограничения и проверки](../docs/migration/mail-extras.md).

«Письма на потом»: личные сроки / откладывание / ожидание ответа, сроки по Москве, отмена и переходы. Snooze скрывает строку только до срока; follow-up использует валидный Message-ID и штатный фоновый проверяющий механизм. [Ограничения и проверки](../docs/migration/deferred-mail.md).

Контакты: карточка, создание/правка/удаление локальных записей, явное сохранение адреса из справочника на телефон. Шаблоны и подпись доступны через «Ещё». Уведомления/виджеты открывают нативные поддержанные маршруты с ожиданием завершения форм; [ограничения](../docs/migration/native-notification-routing.md).
