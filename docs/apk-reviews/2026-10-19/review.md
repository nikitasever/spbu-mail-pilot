## Приоритет 1: не объявлять каждое время срочным сроком

В extractAiBadgeLabel срочность определяется локальными подстроками `срочн`, `защит`, `дедлайн`, `согласован`.
Кроме того, любое распознанное время само по себе включает метку «Срочно».
Это проверка строк, не результат вызова подключённой модели. В испытании ключ ИИ не настраивался, сеть была отключена.

Воспроизведено:

| Вход | Фактический результат | Оценка |
| --- | --- | --- |
| Срочно: согласование до 18:30 | AI: Срочно • 18:30 | Старый дефект исправлен |
| Срочно: ответьте сегодня | AI: Срочно | Часы не выдумываются |
| Приглашение на встречу в 10:00 | AI: Срочно • 10:00 | Само время встречи не доказывает срочность |
| Защита завтра в 15-00 | AI: Срочно | Формат с дефисом не распознаётся этим методом |
| Согласование завершено | AI: Срочно | Завершение ошибочно попадает в срочные по слову «согласован» |
| Срочно: перенос с 15:00 на 18:30 | AI: Срочно • 15:00 | Выбрано отменённое/старое время |
| Прочитанное «Срочно: ответ до 18:30» | null | Для переданного unread=false плашка скрывается |
| Срочно: нужен ответ; превью «Ответьте до 21:05» | AI: Срочно • 21:05 | Извлечение из превью работает |
| Срочно: встреча в 25:99 | AI: Срочно | Некорректные часы не выводятся |

Полные наблюдения: badge-tests.json. Это девять вызовов конкретной функции APK, не полный набор unit/UI-тестов приложения.

### Как исправлять

- Разделить «в письме обнаружено время» и «письмо требует срочного ответа»; время не считать признаком срочности.
- Не применять общий корень «согласован» как срочность; учитывать завершённость и отрицания.
- При переносе/нескольких временах показывать неоднозначность или запрашивать подтверждение, а не выбирать первое совпадение.
- Объединить распознавание дат/времени со штатным парсером приложения, поддержать 15-00, чтобы список и создание события не расходились.
- Локальную подсказку честно подписывать как локальную. AI-результат показывать по фактическому результату модели.
- Закрепить регрессионные сценарии из таблицы в исходниках, когда будет доступен проект этой сборки.

- Не заявляется, что эта сборка объединила все последние функции нашей ветки 0.74-rc.1. Исходники проекта не предоставлены.
- Размеры/обрезание вложений проверялись на метаданных фикстуры. Фактическое скачивание, открытие DOCX/PPTX,
  системный выбор папки SAF и пакетная передача файлов не запускались.
- Не проверялись реальные IMAP/SMTP/CalDAV, справочник, отправка, отложенная очередь, уведомления,
  полная работа AppLock, клавиатура с длинным письмом, поворот и все экраны приложения.
- Это Android 10/API29 в отдельном программном эмуляторе без KVM. Времена установки/холодного запуска и
  зависания системного SystemUI в этой среде не используются для оценки быстродействия APK на телефоне.
- Первичная команда установки превысила лимит ожидания на хосте, но установка завершилась на Android;
  перед пробами проверен точный SHA-256 установленного APK.
- Все письма, пароли и адреса — синтетические; сервер тестового аккаунта 127.0.0.1:1993,
  адрес demo@example.invalid. Реальные данные не использовались. APK не изменён.
- Для проверки первого запуска очищены только созданные нами данные приложения в emulator-5554.
  Исходники рабочей ветки, её версия и канал обновлений не менялись; новый релиз не создавался.
