# Состояние передачи вложений Compose — 28 октября 2026

Найденные дефекты:

- Скачивание из письма включало общий InboxState.busy, отключая действия всего
  экрана, и отбрасывало callback прогресса. Отдельной отмены не было.
- Библиотека файлов выполняла скачивание и чтение списка на одном executor.
- Компоновка SMTP вызывала MailSender.send с null вместо наблюдателя прогресса.
- Сетевой SMTP-вызов удерживал общий NativeDraftStore.gate, блокируя чтение
  хранилища черновиков до ответа сети.
- Отмена локального импорта выставляла флаг, который нельзя проверить, пока
  провайдер файлов не вернёт read/query/open. Диалог экспорта при отмене
  оставался модальным до завершения сетевого чтения.

Исправлено в обоих вариантах с сохранением их существующих возможностей:

1. Загрузка из письма использует отдельные gate/executor и состояние. Общий busy
   не устанавливается. Показываются имя, этап, байты и известный общий объём.
   Отмена сразу возвращает управление UI; старый ответ не может открыть файл.
   После 90 секунд без прогресса этот запрос прекращается в UI с сообщением.
   Смена письма, уход с почтового экрана и фон отменяют активное скачивание.
2. Библиотека файлов скачивает отдельно от чтения страниц. Отмена не уничтожает
   курсор списка; переход к другому письму/папке отменяет старый результат.
3. Системный импорт использует CancellationSignal для query/open и регистрирует
   поток/дескриптор для закрытия вне UI-потока. Поздний поток после отмены не
   допускается к копированию. Неполные файлы очищаются существующим движком.
4. Редактор можно свернуть во время импорта, серверной синхронизации и SMTP.
   Статус остаётся в основном интерфейсе. Редактирование того же письма до
   завершения операции запрещено; это не отключает остальную почту/календарь.
5. SMTP показывает подготовку, подключение, переданные байты, ожидание ответа
   сервера и сохранение копии. Заполнение счётчика байтов не означает доставку.
   Отмена до начала отправки сохраняется; прерывание начатого SMTP не выдаётся
   за безопасную отмену. Неизвестный результат не запускает повторную отправку.
6. NativeDraftFlight резервирует активный черновик отправляемого ящика, не держа
   глобальную блокировку диска во время сети. Другие потоки могут читать список;
   изменение/повторная отправка этого ящика отклоняются до завершения SMTP.
   DISPATCHING/UNCERTAIN по-прежнему сохраняются до внешнего эффекта/при сбое.
7. Диалог экспорта сразу закрывается по отмене. Фоновая очистка и итог видны
   отдельной строкой; завершённые файлы не удаляются. Экспорт оригинала EML тоже
   передаёт cancellation/progress. Неизвестный размер не изображается процентами.
8. Ошибки сети, входа, лимита, исчезнувшего письма и доступа выводятся фиксированным
   безопасным текстом; сырые сообщения сервера, приватные пути и секреты не выводятся.

## Автоматическая проверка

- tools/test-native-transfers.py: асинхронная отмена при блокирующем close,
  поздний stream после отмены, освобождённый/закрытый executor, неизвестные
  размеры, этап подтверждения, исключение преждевременных 100%, защита
  отправляемого ящика без блокировки другого, безопасные сообщения ошибок.
- tools/test-local-attachments.py: MIME/EML/PDF/DOCX, пределы, очистка неполных
  файлов, отмена сохранения до открытия назначения.
- NativeComposerTest/NativeAttachmentsTest: долговечные маркеры отправки,
  неизвестная доставка, отказ диска, stale editor, запрет повторной отправки,
  отмена провайдера и изоляция вложений черновиков.
- Компиляция обоих Android UI. JVM-фикстуры не проверяют прошивку/реальный SAF.

## На телефоне пока не проверено

Скачивание большого PDF с медленной сетью, отмена во время подключения/чтения,
переход к другому письму/календарю, длинное имя и неизвестный размер; добавление
файла из облачного провайдера, отмена зависшего открытия; сворачивание SMTP,
потеря сети до/после DATA, результат после принятия SMTP и сбоя IMAP Sent-copy.
Проверить AppLock, поворот, фон и смену аккаунта. Подтверждение реальной доставки
и работы конкретного провайдера требует телефона и тестового почтового ящика.
