# Исходники интерфейса

## CSS

Редактируйте файлы `ui/styles/*.css`. Порядок задаёт `ui/styles/order.json`.
`assets/app.css` — отслеживаемый сгенерированный файл для Android WebView,
офлайн-загрузки и существующих тестов. Не редактируйте его вручную.

Команды:

- `npm run build:styles` — собрать после редактирования модулей.
- `npm run test:styles` — проверить сборщик и совпадение итогового файла.
- `npm test` — проверка актуальности CSS, сборщик и JavaScript-сценарии.
- `npm run test:layout` — проверка актуальности CSS и браузерные сценарии.
- `python build.py --test --check-only` — генерация CSS и проверки Android/JS.
- `python build.py` — генерация CSS и сборка APK.

Манифест включает каждый CSS-файл ровно один раз. Файлы заканчиваются переводом
строки и читаются как UTF-8. Сборщик не меняет селекторы, комментарии или правила,
не сортирует их и не минифицирует. Запись происходит атомарно, только при изменениях.
Файлы модулей находятся вне `assets`, поэтому APK и WebView получают один локальный
CSS, без сетевых импортов и новых библиотек.

## Владельцы стилей

- `foundation.css`, `shell.css`, `navigation.css`: токены, базовые компоненты и навигация.
- `inbox*.css`, `mail-metadata.css`: список писем, категории, метаданные.
- `reader*.css`, `download-progress.css`, `forms-and-files.css`: чтение и вложения.
- `calendar*.css`, `modals-and-responsive.css`: календарь, диалоги и адаптивность.
- `directory.css`, `contact-index.css`, `contact-card-and-threads.css`: контакты; последний файл также содержит цепочки писем.
- `writing-tools.css`, `transfer-and-controls.css`, `drafts.css`: инструменты письма, передача и черновики.
- `workspace.css`, `digest.css`, `reminders-and-search.css`: рабочие разделы, сводка, поиск и напоминания.
- `compact-layout.css`, `visual-polish.css`: совместимые уточнения нескольких экранов.

Поздние уточнения намеренно сохранены отдельными файлами после базовых правил.
Это первый механический этап: перенос всех правил одного экрана в один файл
без учёта каскада мог бы изменить оформление. Дальнейшее объединение и удаление
повторных правил требует отдельной проверки браузерных сценариев.

## Граница текущего этапа

JavaScript начинает разделяться на независимые модули в 0.69. TypeScript, Preact
и Compose пока не внедрены; текущее состояние описано ниже.

## JavaScript 0.69

Редактируйте `ui/app.mjs` и модули `ui/core`, `ui/mail`, `ui/calendar`,
`ui/contacts`, `ui/compose`. `assets/app.js` — отслеживаемый результат сборки,
не источник для ручного редактирования. После изменений выполните
`npm run build:ui`, затем `npm test` и `npm run test:layout`.

Сборка требует Node.js/npm. `build.py` устанавливает закреплённые зависимости
через `npm ci --ignore-scripts` и собирает UI до компиляции/упаковки Android.
Генератор `scripts/build_ui.cjs` использует esbuild 0.28.2, IIFE-формат,
UTF-8 и ES2022 — возможности, уже используемые текущим WebView-интерфейсом.
Минификация выключена. Результат воспроизводим, записывается атомарно только
при изменениях. Проверки npm отвергают устаревший бандл.

В APK остаётся один локальный `app.js`: браузер не загружает ES-модули,
динамические чанки, внешние библиотеки или сетевые импорты. `esbuild` — инструмент
сборки и в APK не включается. Существующие linkedom/Playwright-тесты используют
тот же файл и те же `data-action`/DOM-селекторы.

Границы:

- `core/markup.mjs`: экранирование и элементы разметки.
- `mail/identity.mjs`: ключи UID/UIDVALIDITY/папки, адреса, инициалы, цепочки.
- `mail/attachments.mjs`: метаданные и отображение размеров вложений.
- `mail/date-hint.mjs`, `mail/copy-age.mjs`, `calendar/dates.mjs`: даты Москвы,
  сроки из письма, время копии и календарные диапазоны.
- `mail/category-rules.mjs`, `contacts/identity.mjs`: нормализация правил и имён.
- `mail/row.mjs`, `mail/reader.mjs`, `compose/render.mjs`: разметка отдельных
  экранов/строк с явно переданным контекстом. Эти модули сами не отправляют письма
  и не запускают запросы.
- `app.mjs`: оставшиеся состояние, контроллеры и регистрация callbacks Pilot.

Это первый этап, не полное разделение всех экранов. Следующие шаги — перенос
оставшихся представлений и контроллеров, затем типизация контрактов `Pilot`.

## Представления почты и календаря 0.70

Разметка списка входящих и цепочек вынесена в ui/mail/inbox.mjs и thread.mjs.
Календарная сетка, выбранный день, карточки событий и результаты поиска находятся
в ui/calendar/render.mjs, item.mjs и search.mjs. Каждый вызов получает текущий
контекст; контроллеры, выбор даты, загрузка, фокус и callbacks Pilot остаются
в ui/app.mjs. Состав DOM, действия, фильтры и порядок событий сохранены.
CSS и фиолетовая тема не изменены. Это продолжение разделения представлений,
без миграции состояния, TypeScript или нового UI-фреймворка.

## Представления контактов, задач и заметок 0.71

Список, карточка и основной экран контактов вынесены в ui/contacts/list.mjs,
card.mjs и render.mjs. Строка задачи и её список находятся в ui/tasks/item.mjs
и render.mjs; заметки — в ui/notes/render.mjs. Данные и функции передаются
при каждом вызове. Загрузка справочника, префиксный поиск, сохранение,
удаление, фокус и обработчики действий остаются в ui/app.mjs.
DOM, порядок задач, фильтры и офлайн-состояния сохранены.
CSS и фиолетовая тема не меняются; APK по-прежнему содержит один локальный бандл.

## Черновики и почтовые диалоги 0.72

Разметка черновика и списка черновиков находится в ui/drafts/item.mjs и render.mjs.
Категории и их диалог вынесены в ui/mail/categories.mjs и category-dialog.mjs.
Очередь расписания, просмотр её копии, диалоги планирования и напоминания находятся
в scheduled-list.mjs, scheduled-preview.mjs, schedule-dialog.mjs и snooze-dialog.mjs.
Текущий контекст и доступные методы Pilot передаются явно. Представления не
отправляют письма и не меняют сохранённые данные; уведомления только читают
доступность через прежний метод. Валидация, защита черновиков, сохранение, отмена,
таймеры и запросы остаются в ui/app.mjs. CSS, DOM-действия и фиолетовая тема сохранены.
