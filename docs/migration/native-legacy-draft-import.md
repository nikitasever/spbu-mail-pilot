# Копирование прежних черновиков в Compose

16 октября 2026. «Ещё → Черновики на телефоне → Черновики прежнего интерфейса».
Явное действие с подтверждением копирует выбранный текст, To/Cc/Bcc, тему,
reply headers и все доступные вложения в отдельный зашифрованный нативный черновик.
Исходная запись, её файлы и серверная копия не изменяются и не удаляются.
UI предупреждает, что обе копии могут быть отправлены вручную: импорт сам не
запускает SMTP/IMAP/планирование и не подтверждает, что прежняя попытка не отправилась.

Загружается account-scoped прежний JSON. Записи с некорректными/повторяющимися ID
и protectedDraftIds существующей очереди исключаются; точная queue-проверка повторяется
при копировании. Число исключённых записей показано. Некорректный список больше
5000 записей отвергается. В нативной коллекции сохраняется общий предел 50 записей;
он проверяется перед копированием файлов и повторно атомарным create.

NativeLegacyDraftPlan проверяет поля/вложения, создаёт новый UUID и убирает старые
serverDraft/attempted/unconfirmed/scheduledMessageId: их ключи не принадлежат новой
копии. Исходные значения не переписываются. Текст сохраняется буквально, без новой
автоподписи, обрезки, HTML-преобразования или автоматического исправления адресов.
Неподдерживаемая/некорректная запись даёт ошибку вместо частичного импорта.

legacyDraftSource сохраняет прежний ID и SHA-256 канонического содержимого.
Перестановка ключей, updatedAt и серверный статус не создают новое содержимое.
Если такая копия ещё есть в нативной коллекции, повтор откроет её, не перезаписывая
последующие нативные правки. Изменившееся содержимое прежнего черновика создаёт новую
копию только по новому явному действию. После удаления нативной записи постоянной
истории импортов нет: новое копирование снова создаст запись. Это копирование,
а не блокировка/удаление прежнего черновика или гарантия отсутствия прошлой доставки.

Файлы читаются из outgoing текущего аккаунта. Проверяются token/path, размер,
доступность и лимиты 10 файлов × 100 MiB. Новые приватные копии получают собственные
token и owner/UUID директорию, fsync перед metadata commit. Отсутствующий,
изменившийся или выходящий за каталог файл останавливает весь импорт; частичный
черновик не создаётся. Исходный JSON повторно сравнивается под ReplyReminderCenter.class
непосредственно перед commit. Конкурентное изменение отклоняет импорт.

NativeDraftStore.gate защищает дедупликацию, выбор и запись. После неоднозначного
AtomicFile-сбоя очистка проверяет записанные ссылки именно нового UUID и не удаляет
возможные закоммиченные файлы. Проверка хранилища с ошибкой оставляет файлы для
сохранности. Исходные outgoing-файлы никогда не очищаются этим кодом.

Прогресс ограничен по частоте; остановка/пауза инвалидируют поколение и проверяются
на каждом блоке копирования. Уже записанная копия остаётся при отмене UI-ответа.
Аккаунт/AppLock проверяются перед чтением/фиксацией и открытием результата. Callback
передаёт точные owner/ID. Снимки хранятся только в ViewModel, не SavedStateHandle;
диагностика не печатает тела/адресатов/ID импорта.

Проверки: native-ui/test-legacy-draft-import.sh — точный текст/envelope, неизменность
источника, fingerprint/idempotence, конфликт snapshot, фильтрация очереди/дубликатов,
опасные пути/метаданные, реальные временные файлы, размеры, остановка частичной
копии и symlink escape. Регрессии коллекции, очереди и серверного плана; прежние
JS server-draft/scheduled сценарии. Kotlin/Java compile и 12 выбранных JUnit.
Реальные SharedPreferences/AtomicFile/Keystore и жизненный цикл Android/IME не проверены
на устройстве. APK и рендеры не создавались.
