# Нативная карточка и личные контакты

Ограниченный блок: NativeContactsModel/Screen и NativeContactEdits. Существующая
фиолетовая Material-тема, UniversityDirectory и account-scoped NoticeCenter.state
сохранены. Новая база не создаётся; это прежний JSON в SharedPreferences,
не отдельное шифрованное хранилище контактов.

## Поведение

Имя/адрес строки открывает карточку с полным адресом и известным номером.
«Написать» передаёт адрес прежнему callback; копирование использует Android
clipboard; «Позвонить» открывает ACTION_DIAL для допустимого номера. Отправка
письма и набор номера автоматически не выполняются. Номер берётся из локального
contacts, затем phoneContacts; тела писем для поиска телефона не загружаются.

Добавление и «Сохранить на телефоне» открывают форму до записи. Локальные записи
можно изменить и удалить с подтверждением. Identity — адрес без учёта регистра;
переименование адреса и отклонение дубликата соответствуют старой форме. Пустое
имя заменяется адресом; поля обрезают внешние пробелы. Back/Отмена защищают
изменённую форму, отмена подтверждения сохраняет текст. Форма остаётся в
ViewModel при повороте; после уничтожения процесса текст не восстанавливается.

Каждая запись перечитывается и сравнивается с исходным snapshot под
ReplyReminderCenter.class. Независимые изменения других контактов сохраняются;
изменение/удаление того же контакта отклоняет устаревшую запись. Неизвестные поля
контакта и остальные коллекции сохраняются. Directory, phoneContacts и
recipientBook не изменяются: после удаления личной записи тот же адрес может
оставаться в истории. Явное сохранение контакта из справочника создаёт только
локальную копию. Account scope, foreground, AppLock и generation проверяются
перед работой и непосредственно перед commit. Ошибка сохраняет редактор.

Отличия от старой формы: неизвестные поля редактируемого контакта сохраняются;
управляющие знаки в имени/номере отклоняются; диалер принимает только обычные
цифры/разделители. Импорт и отдельный экран истории не входят в этот блок.

## API и проверка

NativeContactsScreen(model, write, fullClient) остаётся совместимым. close()
выполняет Back (редактор → карточка/список → почта). Для входящих маршрутов
canExternalNavigation() запрещает уход во время формы/подтверждения/операции;
closeForNavigation() закрывает весь раздел только при разрешённом уходе.

Выполнен `native-ui/test-contacts-edit.sh`: целевой Java policy-набор,
8 одинаковых CRUD fixtures через фактический assets/app.js/WebView DOM и новую
Java-политику, isolated canary неверного fallback имени, существующие
`test-contacts.cjs` и `test-reliability-contacts.cjs`. Сравнение ограничено полями
и результатами этих fixtures; оно не доказывает равенство всего UI или Android
persistence. Дополнительно проверены record CAS, независимые записи, дубликаты,
валидация, неизвестные поля и отсутствие изменений истории/телефонной книги.

В этом блоке не запускались Gradle, APK, рендеры, эмулятор, реальная почта,
справочник или звонки. Компиляция Kotlin интеграции выполняется родительской
задачей отдельно. Android lifecycle/IME/TalkBack/clipboard/диск требуют устройства.

Интеграция: общий Kotlin/Java compile прошёл. Первое сохранение сохраняет базовую форму tasks/notes/events для reloadNativeState старого UI. API canExternalNavigation/closeForNavigation подключён к ожидающим уведомлениям. APK/устройство не проверялись.
