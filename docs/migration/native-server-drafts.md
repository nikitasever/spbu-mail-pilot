# Серверная копия черновика Compose

16 октября 2026. В редакторе добавлены явное сохранение копии на сервере,
прогресс загрузки, остановка соединения и удаление подтверждённой серверной копии.
Локальный автосохранённый черновик остаётся источником текста/вложений. Изменение
текста после загрузки не запускает фоновый APPEND; UI поясняет, что новые правки
нужно загрузить отдельно. Открытие редактора не вызывает IMAP-запись.

Перед сетью сохраняются правки и durable serverDraftAttempted/serverDraftUnconfirmed.
Если запись маркера не удалась, серверная операция не начинается. Ключ — UUID
этого нативного черновика. Используется существующий ServerDrafts.save: ревизия
содержимого, поиск подтверждённой ревизии перед APPEND и сверка UID/UIDVALIDITY.
Повтор после потерянного ACK не создаёт второй экземпляр той же ревизии.
Обновление заменяет только копии с тем же собственным ключом; broad EXPUNGE нет.

Подтверждённая ссылка принимается только с точными key, revision, folder и
положительными строковыми UID/UIDVALIDITY. Метаданные пишутся через прежний
NativeDraftStore revision CAS. Потерянный ответ или неудачная запись подтверждения
оставляет предупреждение о возможной серверной копии, без автоматического повтора.
При конфликте ревизии/нечитаемом хранилище редактор блокирует изменения/отправку,
оставляет показанный текст для копирования и требует закрыть/переоткрыть для сверки.

Удаление требует подтверждения и использует ServerDrafts.removeKnown:
точные folder/UIDVALIDITY/UID/key/revision/DRAFT и UIDPLUS UID EXPUNGE.
Если UIDPLUS нет или ссылка изменилась, удаление не выполняется. Локальный текст
и вложения не удаляются. Если ранее была неподтверждённая загрузка, удаление
известной копии не снимает предупреждение о возможной другой ревизии.

NativeReadGate инвалидирует поколение сразу, закрывает захваченное соединение
в отдельном потоке при остановке/паузе. Уже выполненный APPEND/DELETE отозвать нельзя;
подтверждённые метаданные сохраняются даже после ухода в фон. Прогресс повторно
проверяет аккаунт/AppLock/поколение; автоматического восстановления сетевой операции нет.

После успешной SMTP-отправки нативный редактор и существующий ScheduledMail
пытаются удалить только подтверждённую собственную серверную копию. Ошибка Sent-копии,
удаления либо неподтверждённая серверная загрузка дают предупреждение, сохраняя
SMTP-успех. Повторная отправка этим не разрешается. Прежняя очередь сохраняет
совместимость с существующим draft-key mapping для старых черновиков.

Проверки: NativeServerDraftPlanTest; 35 host-наборов редактора; регрессии очереди;
ServerDraftsTest/ServerDraftRemovalTest с реальными JavaMail объектами и fake folder
(без сети): потерянный ACK, чужие черновики, точные UID, UIDPLUS, отсутствие общего
EXPUNGE. Прежние test-server-drafts.cjs и test-scheduled-send.cjs, Kotlin/Java compile,
выбранные JUnit. Реальные IMAP, Keystore, AppLock, фон и отмена на устройстве остаются
непроверенными. APK/рендеры не собирались.

Не завершено этим пакетом: несколько нативных черновиков, открытие/редактирование
произвольного серверного черновика, перенос прежних WebView-черновиков. Наличие
кнопки серверной копии не означает полного переноса управления черновиками.
