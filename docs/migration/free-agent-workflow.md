# Экономное распределение задач

Роли записаны в `agent-roles.json`. Это памятка маршрутизации задач для координатора, а не автоматически применяемая конфигурация OpenCode. Ограничения соблюдает координатор при каждом запуске.

| Исполнитель | Задача | Когда запускать |
| --- | --- | --- |
| DeepSeek V4.1 Flash Free | Один законченный участок переноса Kotlin/Java, предложение патча | Основной внешний исполнитель |
| MiMo V2.6 Flash Free | Небольшие механические правки, документация, подготовка тестовых данных | Когда задача не требует сложных архитектурных решений |
| Step 5 Preview Free | Независимая проверка жизненного цикла, изоляции аккаунтов, хранения и отправки | Только для сложных изменений с конкретным риском |
| Основной Codex | Выбор следующего участка, интеграция, проверка результата и целевые тесты | Постоянный координатор |

На 15 октября 2026 года все три идентификатора присутствуют в каталоге OpenCode. Реальный запрос успешно выполнен только через DeepSeek. MiMo и Step проверяются при первом полезном задании, без отдельных демонстрационных запросов.

Одновременно запускается один внешний агент. Для каждой задачи координатор передает только нужные файлы и короткий контракт результата. Запуск производится из отдельной рабочей папки через `opencode run --standalone --model <точный идентификатор> --format json --file <файл> <задание>`, с ограничением времени командой `timeout`. Флаг `--auto` не используется. Изолированная рабочая папка сама по себе не является файловой песочницей: неожиданные запросы доступа не одобряются.

Если бесплатная модель недоступна, работа останавливается или координатор выбирает другую явно бесплатную модель из списка; автоматического платного переключения нет. Повторный запуск — только после разбора ошибки. Не каждый патч требует второго модельного ревью: обычные изменения проверяются просмотром кода и подходящими тестами.

Пароли, токены и настоящие письма агентам не передаются. Результат внешней модели — предложение, которое координатор проверяет перед применением. Доступность бесплатных моделей и лимиты могут меняться.

Текущий порядок работы по приложению сохраняется: перенос функций, целевая компиляция и тесты; сборка APK и выпуск — после завершения переноса и общей проверки.
