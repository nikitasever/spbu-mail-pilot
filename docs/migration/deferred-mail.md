# Откладывание и ожидание ответа в Compose

Перенесены legacy openSnooze/saveSnooze/cancelSnooze и replyReminders в общий
NativeMailExtras/Model/Screen. Три независимых массива прежнего account JSON:
responseReminders — личное «мне нужно ответить», snoozedMail — скрытие до срока,
replyReminders — фоновая проверка ответа по Message-ID. Массивы не объединяются.

Меню reader: Отложить письмо / Проверить ответ собеседника. Сроки по Москве,
пресеты и точная дата/время, изменение/отмена. Для follow-up требуется единственный
валидный RFC Message-ID из загруженного body.message; тема его не заменяет.
Сохранение не запускает IMAP/SMTP и не меняет Seen. В срок ReplyReminderCenter
использует прежний hasReply и References/In-Reply-To, с проверкой актуальности
записи перед уведомлением. Нового сетевого планировщика нет.

Snooze скрывает только подходящую точную folder/UIDVALIDITY/UID-ссылку в нативном
списке до at. Серверные папки/флаги и сохранённые строки не изменяются. Compose
пересчитывает активные ключи при сроке/возобновлении coroutine; для длинного ожидания
проверяет часы не реже раза в минуту. При отмене строка доступна сразу, при истечении
возвращается из уже загруженной выборки без автоматического сетевого запроса.

Раздел «Письма на потом»: личные сроки / отложенные / жду ответа. Список показывает
исходное письмо, дату, изменение/отмену и точный переход к reader с возвратом.
Для follow-up читается существующий ReplyReminderCenter.record: answered — ответ
найден, notified — уведомление показано, pending — запланировано/ожидает проверки.
Это состояние последнего обновления; при ошибке сети ответ не объявляется найденным.
Read-only статусы не добавляются в persistent reminder и не влияют на CAS.

Запись под общим lock в свежий JSON, точный record CAS внутри выбранного bucket,
максимум 500 записей на bucket. Другие buckets, метки и неизвестные поля сохраняются.
Повторное изменение заменяет только свою запись. Отмена и новые сроки проходят
штатный NoticeCenter.schedule, отменённые записи проверяет прежний фоновый worker.
Форма удерживается ViewModel; process death не восстанавливает несохранённый ввод.

Проверки: NativeDeferredMailTest, NativeMailExtrasTest, ReplyReminderTest,
MailSnoozeTest; test-mail-snooze.cjs/test-reply-reminder.cjs; ViewModel deferredFormState
и mailExtrasState; Kotlin/Java compilation. Проверены независимость buckets,
точная область, expiry/cancel visibility, неверные/составные/инъекционные Message-ID,
совместимость планировщика, CAS и сохранность формы. Реальные уведомления/сеть/касания
не проверены. Native-маршрутизация из Android-уведомлений остаётся отдельным блоком.
APK/рендеры/выпуск не создавались по указанию пользователя.
