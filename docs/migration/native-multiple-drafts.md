# Несколько черновиков Compose

16 октября 2026. «Написать», ответ/ответ всем, пересылка текста и письмо контакту
создают отдельный черновик. Прежние черновики сохраняются. «Ещё → Черновики на
телефоне» открывает список этого аккаунта: тема, получатель, статус, число файлов,
выбор и создание нового. Удаление редактируемого черновика остаётся в редакторе
с подтверждением; SENT/SCHEDULED закрываются прежними отдельными действиями.
Лимит — 50 записей, включая требующие сверки статусы.

NativeDraftBook хранит активный ID и записи NativeDraft с собственными ревизиями.
NativeDraftStore атомарно шифрует всю коллекцию в прежний account-scoped AtomicFile
с тем же Keystore alias/AAD. Version-1 одиночный черновик читается без потери и
переходит в version 2 при следующей успешной записи. До commit старый файл остаётся
штатным источником восстановления AtomicFile. Предел пакета 32 MiB, проверка до
записи; ошибка размера/шифрования не удаляет прежние черновики. Старый код,
понимающий только version 1, новую коллекцию не читает; формат обратной миграции
не реализован. Записи другого аккаунта, дубликаты и некорректный active отклоняются.

Переключение сохраняет записи и увеличивает ревизию выбранного черновика.
Автоматический выбор оставшейся записи при удалении также увеличивает её ревизию.
Запись/удаление принимаются только для точного активного ID и ожидаемой ревизии.
Старое окно не может перезаписать черновик после переключения туда и обратно.
NativeSendTransaction и NativeScheduleTransaction получают отказ durable-маркера
до SMTP/queue insert, если активный черновик уже другой.

Восстановление ошибки отправки/планирования принимает durable запись только с теми
же owner/ID и содержимым. Другой активный черновик не подменяет состояние старого
редактора; конфликт блокирует изменение/отправку до переоткрытия. Разрешение ручного
повтора дополнительно проверяет точные ID/ревизию. При ошибке добавления вложений
список сохраняемых файлов читается по исходному ID из всей коллекции, а не из
текущего активного письма: переключение не удаляет уже закоммиченные вложения.
Файлы остаются в прежних отдельных owner/UUID директориях, без копирования при выборе.

Возврат отменённого задания создаёт отдельный черновик коллекции. Другие записи не
перезаписываются. Повтор после частичного сбоя находит тот же returned ID и проверяет
его файлы. Очередь подтверждается после native commit; автоматической отправки нет.
Callback открытия передаёт точные owner/ID и не открывает случайно выбранное позже
письмо. Сохранённое состояние Activity содержит только owner/ID; после process death
восстановление проверяет этот ID и ждёт разблокировки AppLock. Несохранённый текст
по-прежнему не обещается восстановить после уничтожения процесса.

Список держится в ViewModel, не сохраняет тела/адресатов в SavedStateHandle; его
диагностический toString скрывает сообщения/аккаунт. Пауза инвалидирует UI-ответы.
Все дисковые операции проходят общий NativeDraftStore.gate. Список не запускает
сеть, SMTP или автоповтор; состояния DISPATCHING/UNCERTAIN/SCHEDULING сохраняют
прежние ограничения после переключения/перезапуска.

Проверки: NativeDraftBookTest — migration v1/v2, лимит 50, copy isolation, stale CAS,
переключение/удаление, статусы, неверный owner/дубликаты, запрет SMTP/queue insert
старому редактору, безопасное принятие delivery markers. 35 прежних host-наборов
редактора, 2 очереди, 1 серверного плана; прежние JS server-draft/scheduled сценарии.
Kotlin/Java compile и JUnit NativeDraftCollectionPrivacyTest/NativeWritingAiPrivacyTest/
NativeNavigationTest. Реальные AtomicFile+Keystore, IME, AppLock и два окна Android
требуют проверки на устройстве. APK и рендеры не создавались.

Остаются импорт WebView-черновиков и открытие/редактирование произвольных серверных
черновиков. Серверная копия выбранного нативного черновика уже поддерживается.
