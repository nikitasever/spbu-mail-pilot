# План завершения переноса

Данные на 17 октября 2026. Это список работ, а не оценка процента или времени.
Сначала требуется [восстановить исходники](source-recovery.md). Утверждения о прежнем состоянии
основаны на журнале работы, а не на коде, который сейчас есть в этой ветке.

- [ ] Сверить с main, включить `native-ui`, исходники, тесты и документацию в одну ветку.
- [ ] Проверить отсутствие приватных данных, целостность UTF-8, зависимости и компиляцию.
- [ ] Зафиксировать base commit, чтобы другие модели делали diff именно против него.

## 1. Расширенный поиск — первый функциональный пакет

Ранее принято только UNSEEN в SearchQuery; полноценная форма/маршрут Compose не завершены.

- [ ] Поля: текст, отправитель, дата с/по, непрочитанные, наличие вложений.
- [ ] Раздельный явный запуск на сервере и в сохранённой почте; подпись области результатов.
- [ ] Неизменяемые проверенные критерии, единый ключ owner/folder/всех фильтров/UIDVALIDITY/snapshot.
- [ ] Вызов существующего MailReader.smartPage и честный локальный фильтр сохранённой выборки.
- [ ] Отмена закрывает блокирующее соединение; устаревшие ответы не меняют новый экран.
- [ ] Пагинация продолжает пустые отфильтрованные страницы с hasMore=true, сохраняет курсор,
  не путает число IMAP-кандидатов с количеством совпадений и не нарушает ограничения NativeMailPage.
- [ ] Ввод не теряет фокус; переход в письмо и назад сохраняет критерии, результаты и позицию.
- [ ] Успех/ошибка/отмена завершают busy; смена области сбрасывает прежний массовый выбор.
- [ ] Проверки диапазонов дат (Москва), полного ключа, пустой страницы, отмены/смены аккаунта,
  повторной загрузки и возврата из чтения.

## 2. Календарь и связи

Исходный package3 отклонён. Переписать/исправить по [обзору](packages3-4-review.md).

- [ ] Управление источниками: просмотр, discovery, выбор коллекции, подключение, удаление с подтверждением.
- [ ] Отдельный выбор события для связи с письмом, работающий без предварительного открытия календаря.
- [ ] Точные owner-bound связи письмо ↔ событие; удаление только выбранной неизменённой связи (CAS).
- [ ] Создание собственной задачи из события и обратный переход с сохранением маршрута.
- [ ] Password privacy, явная отмена, повторная проверка области перед записью, проверка commit.
- [ ] Проверять удаление/изменение выбранного события до записи связи.
- [ ] Сверить наследуемые возможности task → event и ограничения прав серверных календарей.
  Не имитировать удалённое сохранение: для реальных изменений CalDAV отдельно нужны PUT/DELETE,
  права, ETag/If-Match и обработка конфликтов, если этого требует паритет старого клиента.

## 3. Почтовые действия и аккаунты

Исходный package4 отклонён. Не применять целый файл NativeInboxModel из него.

- [ ] Обновление сохранённого пароля: IMAP-проверка, полное CAS исходного Login, сохранение SMTP
  и активного аккаунта; корректный текст — серверный пароль приложение этим не меняет.
- [ ] Массовый выбор в текущей области до 50: явные действия/сброс, подтверждённые результаты,
  ошибки с неопределённым исходом и не начатые операции. Смена области отменяет старый выбор.
- [ ] Массовый перенос между папками — сверить с возможностями ядра, добавить точную UIDVALIDITY
  проверку и безопасную обработку частичного результата; не считать набор UI-кнопок реализацией.
- [ ] Создание/переименование/удаление папок при требуемом паритете — через реальные IMAP-операции
  с подтверждениями и обработкой специальных папок/ошибок.
- [ ] Полные исходные заголовки отдельным ограниченным протокольным путём; текущие From/References/UID
  являются лишь частью сведений. Сохранить предупреждения об усечённых адресах.
- [ ] Скрытые HTML href извлекать в MIME-ядре как безопасные метаданные с реальным адресом назначения;
  не исполнять HTML. Тест должен отличать новую реализацию от старого поиска URL в plain text.
- [ ] Предзагрузка: отменяемое соединение и единый согласованный кэш; исключить перезапись свежего
  snapshot/Seen устаревшим экземпляром OfflineMailStore.

## 4. Вложения, черновики и паритет

По прежнему журналу уже были реализованы текущая папка библиотеки файлов, пагинация, открытие,
SAF-экспорт, передача, пересылка оригинала EML, собственные серверные копии черновиков и редактируемые
копии произвольных серверных черновиков. Это необходимо проверить в восстановленных исходниках.

- [ ] Сопоставить с WebView поиск файлов по всем папкам, офлайн-индекс и экспорт по разным письмам.
- [ ] Сверить управление произвольными серверными оригиналами черновиков. Не делать небезопасную
  замену/удаление без точного UID/UIDVALIDITY/UIDPLUS и защиты от потери изменений.
- [ ] Проверить сохранность всех уже перенесённых путей: composer, локальные черновики, durable queue,
  интервал отмены, неопределённый результат SMTP, серверная Sent-копия, вложения/EML и права просмотра.
- [ ] Составить таблицу по WebView-функциям: legacy entry → Compose entry → реализация/ограничение → тест.
  Любой оставшийся переход в старый клиент требует явного решения, а не отметки «всё перенесено».

## Как раздать задачи другой модели

После восстановления дать точный base SHA, UX-CONTRACT.md, DESIGN.md, нужные исходники и тесты.
Пакеты: A — поиск; B — календарь; C — аккаунты/почтовые действия; D — файлы/финальный паритет.
Разные пакеты могут затрагивать ComposeInboxActivity/NativeInboxModel: согласовать владение файлами,
иначе интегрировать последовательно. Входные условия: обычный UTF-8 unified diff; без откатов прежних
исправлений, удаления тестов, APK/версий/реальной почты; приложить команды и фактические результаты.
Каждый пакет принимается отдельно после проверки, а документация обновляется по итоговому поведению.
