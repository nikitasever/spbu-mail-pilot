# Библиотека файлов в Compose

16 октября 2026. Разработческое изменение, без APK и релиза.

«Ещё → Файлы писем» открывает серверную библиотеку текущей папки выбранного
аккаунта. Поиск выполняется явно по имени файла, без поиска внутри содержимого.
Файлы не скачиваются при выдаче результатов: показываются MIME-метаданные,
отправитель и тема. Вложенный message/rfc822 показан как отдельный EML; inline
изображения исключены по тем же правилам, что в чтении письма.

Страницы обрабатывают по 50 UID. Отдельно показаны число найденных файлов и
число обработанных писем в снимке папки. Пустая страница с hasMore не считается
окончанием поиска: есть «Проверить следующие 50 писем». Размер файла в карточке
подписан как серверный (может быть transfer-encoded), прогресс скачивания —
реальные обработанные байты. После паузы/отмены продолжение требует обновления.
Автоматического сетевого обхода всей папки на каждый введённый символ нет.

Курсор связан с folder, UIDVALIDITY, query и snapshot. NativeFilePage проверяет
прогресс offset, диапазон страницы, точные строковые UID (включая >2^53), имена и
MIME-пути, устраняет повторяющиеся UID+path и копирует только необходимые поля
заголовка. Не больше 5000 результатов в памяти; превышение сообщает об уточнении
поиска, не обрезает выдачу молча. Это поиск в одной папке; объединение всех
папок/аккаунтов и офлайн-индекс здесь не реализованы.

Открыть/Поделиться скачивают один точный MIME-путь с проверкой UIDVALIDITY через
общий AttachmentTransfer (до 100 МиБ). Проверяются account, AppLock, поколение
операции и канонический путь кэша. Страница и скачивание имеют отдельные захваченные
соединения; закрытие, уход в фон и отмена инвалидируют их вне UI. Устаревшие
ответы/прогресс не меняют экран; незабранные локальные файлы удаляются.

«Сохранить» использует существующий NativeExportModel и Android SAF, не создаёт
новый механизм выдачи доступа. «К письму» использует NativeInboxModel.openLinked
и возвращает в сохранённую библиотеку по Back. Просмотрщики/системная передача
проходят общий showFile и read-only URI grant. Никакой записи в OfflineMailStore,
смены Seen или SMTP библиотека не выполняет.

Проверки NativeFilePageTest: пустая страница с продолжением, неверный/stale
folder/query/validity/snapshot, отсутствие прогресса, глубокие копии, дедупликация,
нечисловые JSON UID, безопасные пути, исключение лишних заголовков, индекс EML без
getContent/getInputStream и read-only fixture с заранее заданным UID-снимком.
Поиск UID SEARCH на реальном сервере этим fixture не проверяется.
Дополнительно: SearchAndFilesTest, MailAttachmentsTest, пересылка EML, регрессии
редактора, privacy JUnit состояния и compile Kotlin/Java.

Нет устройства/реального сервера: сетевые задержки, SAF, системные просмотрщики,
TalkBack, поворот/процесс и AppLock требуют отдельной приёмки. Рендеры и APK
отложены по указанию владельца.

Итог: перечисленные host/JS-проверки, Kotlin/Java compile и 12 выбранных JUnit прошли. DESIGN.md lint: 0 ошибок, 6 прежних предупреждений.
