# Сводка почты в Compose

16 октября 2026. Исходники, без APK, публикации и запросов к реальной почте/Google.

## Пользовательский сценарий

1. В списке почты «Ещё → Сводка почты» доступна при разрешённом нейроанализе. Снимок загруженных заголовков текущей папки открывается без чтения тел и без обращения к Gemini. При активном поиске/фильтрах это всё ещё загруженный список папки, что прямо написано на экране; это не все письма сервера и не только видимые представители цепочек.
2. Пользователь выбирает от 1 до 20 конкретных писем. «Выбрать первые 20 загруженных» — отдельное явное действие. Ни одного письма по умолчанию не выбрано.
3. «Подготовить выбранные письма» читает тела через существующий IMAP BODY.PEEK. Требуются сеть, разрешение анализа и сохранённый ключ. Каждый ответ проверяется по исходным folder/UID/UIDVALIDITY. Тексты режутся общим DigestBatch до 4000 UTF-16 units, без разрыва surrogate pair; заголовки ограничены. Вложения/пароли/посторонние поля не переносятся в подготовленный набор.
4. До обращения к Google показываются подготовленные тексты, пометки обрезки и список недоступных писем. Даже полностью успешная подготовка требует второго нажатия «Отправить N писем в Gemini». Частичный набор никогда не отправляется автоматически.
5. Результат — краткая сводка, пункты и подписанные переходы к исходным письмам. Номер источника адресует успешно подготовленный массив, а не первоначальный выбор: при выпадении письма нумерация не сдвигает ссылку на чужой UID. Указанные моделью неизвестные/дробные/пустые ссылки отсекает существующий GeminiDigest.parse.
6. Открытие источника использует точный account/folder/UID/UIDVALIDITY через существующий linked-reader. Back возвращает к сводке; настройки ИИ открываются отдельно. Автоматического Seen, SMTP, создания задач/событий или изменения текста письма нет.

## Состояние и отмена

NativeDigestModel хранит выбор, тексты и результат только в памяти ViewModel. SavedStateHandle/диск для сводки не используются; диагностический toString не содержит темы/отправителя/тела/результата. После смерти процесса сводка не восстанавливается. Исходный список и промежуточный выбор ограничены; курсор сервера в сводку не переносится.

Работа защищена foreground/AppLock, свежим активным аккаунтом, разрешением анализа, моделью, versioned AiVault snapshot и generation gates. Отмена и onPause немедленно инвалидируют поколение; закрытие IMAP/HTTPS выполняется вне UI-потока. Захваченная cancellation закрывает именно старое HTTP-соединение: задержанная отмена не затрагивает новый запрос. На resume не запускаются подготовка/анализ; выключение анализа очищает подготовленный результат, смена модели возвращает к явному подтверждению подготовленных текстов.

Back во время запроса сначала отменяет его. Отмена не отзывает уже переданные Google данные. Повторы только ручные. Ошибка или изменение конфигурации перед показом результата переводит экран обратно к предпросмотру вместо зависшего состояния загрузки. Фиксированные сообщения HTTP 403/404/429 отображаются без сырого тела ответа сервера.

Подготовка имеет бюджет 60 секунд, проверяемый между письмами; блокирующий IMAP ограничен собственными socket timeouts. Это не обещание жёсткого общего дедлайна. Неудачное соединение сохраняет выбор для ручного повторения. Источники привязаны к исходной папке и версии; перемещённое/удалённое письмо не подменяется по теме.

## Проверки и оставшееся

`native-ui/test-ai-settings.sh` включает NativeDigestPlanTest: области аккаунта/папки/версии, границы/дубли/типы ссылок, неизменяемость плана, соответствие тела запросу, исключение секретов/вложений и нумерация частичного набора. GeminiCancellationTest проверяет отключение до записи тела, отмену на EOF и задержанную отмену старого соединения. Существующие GeminiDigest/DigestBatch fixtures проверяют ограничения payload и ответов.

NativeDigestPrivacyTest проверяет диагностическую границу и совместимость точного источника с linked-reader; Kotlin/Java компилируются, навигационные/privacy regressions выполняются отдельно. Это не тест реального IMAP, Google API, Android lifecycle или геометрии экрана. Рендеры и финальный APK отложены по запросу пользователя.

Остаются ИИ-инструменты редактора и передача редактируемого текста сводки наружу. Серверный поиск/загрузка дополнительных заголовков выполняются в исходном списке почты; сводка сама их не подгружает.
