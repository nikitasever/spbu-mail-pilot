# Native signature and writing templates

NativeWritingSettingsModel and NativeWritingSettingsScreen replace the legacy settings-side writing popup. They reuse the Activity's purple InboxTheme, Material3 fields/dialogs, Russian copy, scrolling content, and keyboard/system insets. The screen provides a signature editor, automatic-insertion toggle, template list, create/edit, and confirmed delete. It does not insert text outside the composer.

Integration: retain `NativeWritingSettingsModel(Application)` with the Activity's ViewModel provider; call `resume()` / `pause()` with Activity lifecycle and `open(owner)` with `NoticeCenter.scope(activeLogin)`. Render `NativeWritingSettingsScreen(model)` when `model.state.open`. `back()` handles editor/list navigation and dirty confirmation. `canExternalNavigation()` blocks external navigation during any editor, deletion confirmation, or mutation; after it returns true, `closeForNavigation()` closes the list. Dirty Back shows an app-owned confirmation; its safe action initially receives focus. Cancellation preserves entered values.

Persistence uses the existing per-account NoticeCenter.state JSON and ReplyReminderCenter.class monitor. NativeWritingSettings is a host-testable policy helper: template mutation compares only the selected raw record and retains other records/order; signature mutation compares only changed signature fields and keeps concurrent unrelated settings, including changes to the other signature field. Save captures owner and checks foreground, AppLock, and current credentials before work and immediately before commit. Generation checks suppress stale reads. Write failure/conflict keeps editor or deletion confirmation available for retry; settings never rewrite an existing draft.

Limits match ui/app.mjs: trimmed nonblank template title up to 180 UTF-16 units; nonblank body up to 100000 units, retained verbatim; signature up to 4000 units with blank allowed; at most 100 templates when creating. Existing larger libraries remain intact and are shown without truncation. Edited templates keep ID and order. Invalid legacy entries are retained during mutations; only valid templates appear in the list. Ambiguous duplicate IDs reject edits/deletes; malformed collection/settings shapes reject writes rather than replacing data.

Focused verification: `PATH=/workspace/scratch/java-tools:$PATH native-ui/test-writing-settings.sh` passed NativeWritingSettingsTest and NativeWritingToolsTest. Coverage includes unrelated record/settings preservation, independent signature-field merge, stale target conflicts, source immutability on rejection, edit/delete/order, literal text, length limits, old libraries over 100, malformed state, duplicate IDs, and existing composer insertion policy. No network, Gradle, APK, screenshot, release, or live-service operation ran. The parent integration owns Kotlin compilation; device geometry, accessibility interaction, process-death recovery, and real Android SharedPreferences commit failures are not claimed verified here. Unsaved editor state survives retained ViewModel recreation but is not saved across process death, matching the existing local form contract.

Parent integration: Activity navigation/lifecycle wired, Kotlin/Java compilation passed. Selected template extension fields are retained on edit; first saves seed tasks/notes/events for legacy reloadNativeState compatibility. APK/device/IME checks remain deferred.
