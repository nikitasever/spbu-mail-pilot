# Нативные действия с письмами — архив, спам, корзина, папка

Legacy: MailReader.moveMail и ui/app.mjs handleMailActions/renderRowActions.
Прежние архив/корзина используют тот же протокольный путь. Добавлены Junk/Spam
и выбор существующей папки, без создания папок и без широкого EXPUNGE.

Все действия запускаются явно из меню открытого письма и требуют подтверждения.
Отмена диалога не обращается к серверу. Сохранённое тело нужно явно обновить
с сервера, чтобы открыть действия переноса. Временный связанный reader не переносит.
Назначение проверяется на сервере: существующая папка с HOLDS_MESSAGES, отличная
от источника. Для системных папок используются атрибуты, затем известные имена.
Источник проверяется по точному UID и UIDVALIDITY до и после READ_WRITE reopen.
Сервер обязан поддерживать MOVE. COPY+DELETE fallback и окончательного удаления нет.
Закрытие папки всегда без expunge. После операции восстанавливается READ_ONLY.

Перед командой повторно проверяются foreground/AppLock/аккаунт/пароль и свежий
общий JSON. Задачи, напоминания, snooze и eventMailLinks защищают рабочую ссылку:
для переноса её сначала надо убрать в полном клиенте. Некорректные данные связей
отклоняют перенос. Проверка повторяется после подготовки папок перед MOVE.
Внешний сервер и локальные ссылки не образуют распределённую транзакцию.

Во время операции Back и новые действия блокируются. Обычный уход в фон снимает
неподтверждённый диалог, но не теряет busy/outcome уже начатой операции.
Сетевой write не использует read-gate cancellation и не перезапускается.
Подтверждённый результат удаляет строку только из текущей сессии, закрывает reader,
инвалидирует пагинацию; старый общий офлайн-кэш не перезаписывается.
Фильтр подтверждённых переносов в памяти скрывает такую строку при повторном чтении
старой сохранённой страницы. После process death доступен прежний снимок кэша,
помеченный как сохранённый; перенос недоступен без свежего online-body.

Если подтверждение потеряно, автоматического повтора нет. Reader остаётся на месте,
показывает неопределённый результат; перенос заблокирован до успешного явного
обновления письма/списка с сервера. Откат уже выполненного MOVE отсутствует:
новый UID назначения не предполагается и не выдумывается.

Проверки: MailMoveTest (реальный MailReader над fake IMAPStore/IMAPFolder),
NativeMailMovesTest и прежний test-inbox-system.cjs. Проверены MOVE capability,
точные UID/UIDVALIDITY, источники/назначения, Unicode, Junk/custom-folder,
повторная проверка перед командой, READ_ONLY и отсутствие retry после lost ACK.
Тест ViewModel moveLifecycle проверяет сохранение busy/исходного письма при pause,
блокировку Back во время write и закрытие неподтверждённого диалога.
Компиляция Kotlin/Java выполняется отдельно. Реальная сеть/касания не проверялись.
APK, скриншоты и выпуск для этого блока не создаются по указанию пользователя.
