# Открытие серверных черновиков в Compose

16 октября 2026. Черновики на телефоне → «Черновики на сервере».
Явное открытие подключается к текущему аккаунту, находит папку через общий
DraftFolder (Special-Use \Drafts, затем Drafts/Черновики), читает страницы по 50
UID. UI показывает только DRAFT без DELETED, число загруженных черновиков отдельно
от числа всех записей папки, продолжение и явное обновление. Закрытие/пауза
инвалидируют курсор и закрывают соединение вне UI-потока; продолжение требует
обновления. Никакой автоматической записи/отправки при открытии списка нет.

«Открыть для редактирования» с подтверждением создаёт отдельную нативную копию.
Если точные folder/UIDVALIDITY/UID уже связаны с нативной записью либо подтверждённой
собственной серверной копией, открывается существующий нативный черновик с его
последними правками. Содержимое не заменяется серверной старой версией.

MailReader.serverDraft проверяет настоящую папку черновиков, UIDVALIDITY и наличие
UID; заново открывает READ_ONLY и выставляет PEEK. ServerDraftRead требует DRAFT,
отвергает DELETED, получает To/Cc/Bcc с отображаемыми именами, тему, reply headers,
полный текст и отдельные MIME-ссылки на вложения. MailText.readComplete использует
строгое декодирование и предел 100 000 UTF-16 единиц: превышение/ошибка кодировки
отклоняют открытие вместо незаметного сохранения обрезанного текста. Обычный
режим чтения письма по-прежнему использует прежний ограниченный preview reader.

Предпочитается plain text в multipart/alternative. HTML-only явно превращается в
обычный текст; подтверждение и редактор предупреждают об отсутствии оформления
и встроенных изображений. Текущий аккаунт остаётся отправителем; From исходного
серверного письма не подменяет SMTP-настройку. Подписанные/зашифрованные структуры,
несколько неоднозначных текстовых секций, неподдерживаемые thread headers или
более 10 файлов отклоняются; исходник остаётся доступен в прежнем клиенте.
Это не редактор произвольного MIME/HTML с сохранением исходного оформления.

Все вложения загружаются через прежний AttachmentTransfer: PEEK, проверка полного
потока, encoded/decoded limits, отмена; до 10 файлов по 100 MiB decoded. MIME path
и имена проверяются. Приватные owner/UUID файлы синхронизируются до atomic metadata
commit. После загрузки текст/метаданные/флаги серверного исходника читаются заново;
изменение отклоняет импорт. Родной snapshot folder/UID/UIDVALIDITY не заменяется
по теме письма или порядковому номеру.

Перед commit повторно проверяются foreground/AppLock/аккаунт/поколение. Поиск
существующей нативной копии и создание выполняются под NativeDraftStore.gate.
Если ошибка AtomicFile могла случиться после commit, очистка не удаляет файлы,
на которые уже ссылается новый UUID. При сбое чтения метаданных файлы сохраняются
для безопасности. Исходник сервера никогда не удаляется и не переписывается.
Сохранение отредактированной копии на сервере использует уже реализованную явную
команду редактора и создаёт/обновляет собственную копию нового UUID.

Тела/Bcc не попадают в SavedStateHandle или toString состояния списка. Старый
ответ и старая отмена не отменяют новый запрос. После background нет автоматического
повтора. Уже закоммиченная копия остаётся при потере UI-callback; повтор открывает её,
пока запись существует. UI предупреждает не отправлять серверный исходник и копию.

Проверки: native-ui/test-server-draft-copy.sh — реальные JavaMail MIME объекты и
fake folder: точный Unicode/Bcc, отсутствие Seen, READ_ONLY и запрет неверного
folder/UID/UIDVALIDITY, полный текст/ошибки кодировки/лимиты, plain alternative,
HTML marker, отсутствие чтения бинарных payload до скачивания, native reference
isolation и сохранение локальных правок. Регрессии 35 host-наборов, коллекции,
прежнего импорта; legacy JS server-drafts/attachment-badge/mail-body. Kotlin/Java
compile и 13 выбранных JUnit. Реальный IMAP/PEEK, Android Html conversion,
Keystore/AtomicFile, IME и AppLock/сеть на устройстве не проверены. APK и рендеры
не собирались. Замена/удаление произвольного серверного оригинала отдельной командой
не добавлены этим пакетом.
