# Непринятые package3-calendar-links / package4-mail-hardening

Исторический разбор исходных патчей, а не окончательный вердикт о восстановленном ZIP.
17 октября получен полный объединённый исходный проект; часть описанных ошибок в нём уже исправлена.
Актуальные результаты — в [проверке импорта](source-import-review.md).

Перенесено из проверки 16 октября 2026. Это обзор присланных патчей, а не дефектов текущего
GitHub main: эти изменения туда НЕ применены. Исходные файлы патчей в новой среде отсутствуют.
Номера строк — в извлечённых файлах тех пакетов. Для исправления вернуть сами исходные патчи
или актуальный исходный код, повторить проверку против восстановленной базы.

## Блокеры

1. **Нет зависимости расширенного поиска.** NativeInboxModel ссылается на NativeMailSearch.Criteria
   и filterOffline, но эти определения отсутствуют в текущей проверенной базе и не включены в пакеты.
   package3 также содержит форму поиска без соответствующих изменений состояния/модели.
   Включить полный поисковый пакет либо убрать посторонние изменения поиска из календарного/почтового.

2. **Постоянный busy после загрузки.** В package4 NativeInboxModel.kt:385,429–432 заменён конструктор
   InboxState на state.copy; busy=true устанавливается при начале, но busy=false на успехе не передан.
   Старые selected/body/selectedRefs/pageExpired тоже не сбрасываются явно. Это блокирует действия
   после загрузки и сохраняет состояние прежней области. Нужна явная политика сохраняемых полей.

3. **Обновление пароля меняет текущий ящик.** NativeAccountsModel.kt:121–130 вызывает v.save(target).
   CredentialVault.save → SavedAccounts.save всегда делает target активным. Изменение неактивного B
   при активном A переключает на B, а password-ветка не требует restart.
   Подтверждено локальным примером с фиктивными ящиками. Сделать атомарное обновление без изменения
   activeId, сравнить весь исходный Login, включая пароль и SMTP. Проверка только identity недостаточна.
   UI «Сменить пароль» неточен: реализуется обновление сохранённого пароля, а не его смена на сервере.

4. **Испорчена кодировка package3.** Вложение имело внешнюю UTF-16LE-структуру с повреждённым BOM,
   моджибейк CP866 и 762 последовательности EF BF BD. После снятия оболочки русские подписи оставались
   повреждёнными («╨…뿯▽…»). Нужен повторный экспорт UTF-8 из исходников с правильным текстом.
   Перекодирование уже испорченного файла не гарантирует восстановления текста.

## Календарь

5. **Защита жизненного цикла недостаточна.** submitConnect/chooseDiscovered/confirmRemoveSource/
   confirmUnlink/linkMailToEvent проверяют актуальность преимущественно при публикации результата.
   Сам commit может пройти после закрытия, AppLock или смены аккаунта. Проверять допустимость операции
   и область непосредственно перед мутацией; явно определить отмену и необратимый этап подтверждённой
   операции. Не считать скрытие callback отменой записи. Добавить тесты задержанных ответов.

6. **Нет подтверждения записи и CAS удаления связи.** confirmUnlink, строка 264, игнорирует результат
   SharedPreferences.commit(); успех может быть показан без сохранения. Удаление по одному id
   не сравнивает текущую связь с выбранным снимком. Проверять commit и сравнивать запись под общим lock.
   При изменении/удалении связи другим путём возвращать конфликт, не удалять обновлённую запись.

7. **Пароль в состоянии.** CalendarState хранит connectPassword и стандартный data class toString;
   pause/close его не очищают. Добавить редактированный toString, очистку при уходе/закрытии/смене
   аккаунта и privacy-тест. Это риск вывода при диагностике, а не факт произошедшей утечки.

8. **Пустой выбор события на чистом запуске.** linkEvent в ComposeInboxActivity вызывает calendar.load(false),
   но load выходит при state.open=false; owner также может быть не задан. Нужен самостоятельный
   owner-bound picker с загрузкой, повтором, ошибкой и проверкой актуальности выбранного события.
   Нельзя зависеть от того, открывал ли пользователь основной календарь раньше.

## Почта

9. **Массовый выбор не привязан к области.** selectedRefs не очищается при смене папки/поиска/загрузке;
   toggleSelection не проверяет принадлежность строки текущей выборке. Перед действием нужен полный
   снимок owner/folder/criteria/refs; смена области отменяет старый выбор. Batch обновляет seenFlags
   в worker, тогда как существующие пути используют UI-поток — выбрать одну модель синхронизации.
   Финальный check(currentOwner()==owner) находится за try; смена аккаунта может оборвать worker без
   штатного завершения. Разделить подтверждённые успехи, ошибки с неизвестным результатом и неначатые
   операции; не заявлять точный итог только по числу исключений. Защитить мутации от пересечения с загрузкой.

10. **Ключи поиска расходятся.** ComposeInboxActivity:397,411 использует state.query в ThreadScope и
    listPosition, а модель уже ждёт criteria.key(). При одинаковом тексте и разных From/датах теряются
    позиции и согласованность цепочек. Использовать один полный ключ во всех местах.
    «Найдено N из total» неверно описывает smartPage.total: это число IMAP-кандидатов до постфильтра.
    Проверить пустую страницу с hasMore=true, честные счётчики и ограничения размера NativeMailPage.

11. **Предзагрузка без полноценной отмены/слияния кэша.** prefetchBodies создаёт отдельный MailReader
    без прикрепления к gate, поэтому счётчик не прерывает блокирующий connect/body.
    Долгоживущий OfflineMailStore держит свой snapshot; общий lock записи не сливает его со свежим
    состоянием другого экземпляра. Нужны закрытие соединения при отмене и единый repository либо
    актуализация+merge под общей синхронизацией, включая seenRevision. Не затирать свежие флаги/страницы.

12. **Заявления о ссылках/заголовках превышают реализацию.** NativeReaderActions получает body.text;
    MailReader.extract преобразует HTML в plain text. Новый regexp не увидит скрытый href, которого
    нет в отображаемом тексте. Тест NativeReaderTargetsTest проходил также на СТАРОЙ реализации.
    Нужны отдельные MIME-метаданные ссылок, entities, проверка URL/адреса назначения без исполнения HTML.
    References/rawFrom/UID — часть сведений, не полный набор исходных заголовков. В NativeReaderDetails
    одновременно удалено предупреждение incomplete; сохранить его для усечённых/неразобранных адресов.

## Что проверялось ранее

- Изолированно компилировались и выполнялись присланные NativeMailLinksTest и NativeReaderTargetsTest: PASS.
- Присланный NativeReaderTargetsTest с прежней реализацией: тоже PASS — покрытие новой функции не доказано.
- Локальный Java probe подтвердил смену activeId через save и отсутствие Criteria/filterOffline в базе.
- Статически проверены отсутствие busy=false и очистки selectedRefs на завершении loadInbox.
- Полная Kotlin/Android-компиляция этих пакетов НЕ подтверждалась: комплект зависимостей неполный.
- APK, реальные IMAP/SMTP, контакты, устройство и рендеры не запускались.

## Готовое задание автору

Вернуть правильный UTF-8 и сделать обычные unified diff против точного коммита восстановленной базы.
Не объявлять существующие файлы новыми, не подменять целые файлы из другой ветки. Включить все
обязательные классы и тесты. Исправлять в порядке: зависимости → busy/selection → пароль/CAS/activeId
→ lifecycle/commit → privacy → точность реализации и статуса. Контакты, черновики и очередь вне задачи
не изменять. Сохранить прежние тесты; добавить регрессии на перечисленные ошибки. Не собирать APK,
не повышать версию и не обращаться к реальной почте. Приложить фактические результаты целевых тестов
и компиляции исходников. Документацию обновлять только после реализации работающего UI-пути.
