# Native-переходы из уведомлений и виджетов

В native manifest зарегистрирована ComposeInboxActivity/singleTop. UiEntry выбирает
её только при наличии включённой Activity в установленной сборке; обычный build.py
по-прежнему получает MainActivity. Прямых зависимостей root Java от Compose нет.
NoticeCenter (mail/tasks/personal/follow-up) и MailWidget используют этот resolver.
Уведомления очереди отправки пока направлены в прежний экран, до переноса очереди.

NativeOpenTarget принимает только mail/tasks/mailbox/calendar, ограничивает payload,
проверяет account/folder/UID/UIDVALIDITY, отвергает неоднозначные extras и неизвестные
маршруты. В SavedStateHandle хранится только компактная ссылка, без текста/пароля.
Новый валидный intent заменяет ожидающий, старый completion не стирает новый.
Полученный intent очищается от принятых extras, восстановленный pending не дублируется.

Переход ждёт resumed/unlocked и окончания редактирования/подтверждений/операций всех
нативных моделей. Открытая форма не сохраняется/удаляется принудительно: баннер даёт
убрать ожидающий переход. После завершения формы маршрут применяется автоматически.
Детальные карточки/списки можно закрыть; редакторы/мутации защищены.

Mail открывает точный reader через существующие cache/BODY.PEEK guards, без Seen.
Back сохраняет подходящий текущий список либо читает сохранённую страницу нужной
папки. Виджет Mail открывает INBOX, Calendar — нативный календарь. Tasks открывает
native workspace и подчиняется настройке showTasks существующей модели.

Письмо другого сохранённого аккаунта передаётся прежней проверенной маршрутизации
MainActivity с сохранением target. При отсутствии аккаунта вход доступен там же.
Виджет/задачи другого аккаунта не открывают чужие данные: сообщается необходимость
выбрать нужный ящик. Новые task notices включают openTasksAccount; прежний MainActivity
также проверяет его. Автопереключение native аккаунтов остаётся отдельным блоком.

AppLockAware добавляет безопасный callback после разблокировки без зависимости от
Kotlin. Compose возобновляет модели, а окно всегда сохраняет FLAG_SECURE даже при
выключенной опциональной блокировке. Старый MainActivity callback сохраняется.
Это исправляет отсутствие возобновления нативной загрузки после успешной биометрии.

Проверки: NativeOpenTargetTest, MailNoticeTargetTest, AppLockSessionTest,
test-widget-navigation.cjs/test-app-lock.cjs; NativeNavigationTest с SavedStateHandle
(восстановление/замена/exact consume); совместная Kotlin/Java-компиляция интеграции
контактов и writing settings. Новые пути Activity/PendingIntent, реальная биометрия,
FLAG_SECURE/recents и устройство не проверены, APK/рендер/релиз не создавались.
