# Рабочая почта для Windows — первый прототип

Локальное приложение Tauri 2 с веб-интерфейсом. Отдельный сервер не нужен:
оболочка сама запускает JVM-процесс по stdin/stdout. Java-runtime входит в
установщик. HTTP/TCP-порт для общения частей приложения не открывается.

Первый сценарий: вход по IMAP/TLS, реальный список папок, поиск и пагинация,
чтение по folder/UIDVALIDITY/UID без изменения Seen. Android-код не копируется
в репозиторий: build-engine.py генерирует только две версии исходников с заменой
android.text.Html на настольный HTML-to-text адаптер. Остальные протокольные
классы компилируются из существующего src/. APK на этом этапе не выпускается.

Это не полный перенос APK. Пока нет офлайн-писем, серверных черновиков, списка нескольких
сохранённых аккаунтов, записи событий календаря, экспорта контактов,
Gemini и системных уведомлений. Вложения сохраняются через диалог Windows (до 100 МиБ) и открываются отдельной
кнопкой в системном приложении. Для исполняемых файлов и активного содержимого
доступно только сохранение. Загрузки используют отдельное IMAP-соединение и поток:
чтение и навигация доступны во время скачивания. Панель загрузок показывает прогресс,
отмену, ошибку/повтор и результат; выбор папки не скрывает загрузку. Временные
файлы удаляются после операции; существующая цель заменяется только после успешной
загрузки и копирования. Письма на сервере не меняются.
HTML отображается как текст; удалённые изображения не загружаются.

## Проверка разработки

Нужны Node 24, Python 3, полный JDK 17+ и Rust stable. Для локального Tauri на
Windows нужны стандартные Microsoft C++ build tools и WebView2. Это инструменты
разработчика: владельцу установщика Java/Node/Rust/терминал не требуются.

Из корня репозитория:

```sh
python -c "import build; build.dependencies()"
python desktop/tools/test-engine.py
python desktop/tools/build-runtime.py
cd desktop
npm ci
npm test
npm run build
npm run tauri -- dev
```

`npm run dev` отдельно открывает только интерфейс в браузере: там подключение
к почте намеренно недоступно, нет фальшивого успешного входа. `npm run tauri --
build` собирает установщик Windows. Windows-проверка и артефакт настроены в
.github/workflows/desktop-windows.yml. Публичный выпуск не означает проверку
на пользовательском почтовом сервере.

## Безопасность и границы

Команды ограничены capabilities/connect/disconnect/folders/page/body/cancel/attachment/send.
Нет команды произвольного выполнения кода или записи по пути, полученному от WebView.
SMTP отправляется только из зарегистрированного нативного черновика по кнопке.
Выбранные файлы копируются в приватную временную папку (до 10 файлов, суммарно
100 МиБ), так что изменение оригинала после выбора не меняет отправку.
После нажатия есть 10 секунд отмены до SMTP; после начала передачи отмена доставки
не обещается. Подключение использует TLS или обязательный STARTTLS и пароль
активного IMAP-сеанса. SMTP-параметры и адрес отправителя доступны в редакторе.
Непосредственно перед SMTP записывается долговечная квитанция попытки без текста,
адресов и пароля. Неизвестный результат блокирует повтор. Подтверждение SMTP
записывается до независимого IMAP-сохранения копии в «Отправленных»; ошибка копии
никогда не приводит к повторной SMTP-отправке. Это подтверждение приёма сервером,
а не гарантия доставки получателю. Квитанции хранятся в app-data/send-receipts.
Для каждого host/port/user сохраняется один активный локальный черновик: текст,
параметры SMTP и выбранные файлы. Метаданные и каждый файл зашифрованы отдельно
Windows DPAPI; контекст шифрования связывает владельца/ID/файл. Автосохранение текста
не шифрует заново большие вложения. Сохранение атомарное; старые ревизии не
перезаписывают новые. Временные рабочие копии выбранных файлов остаются обычными
файлами в приватной временной папке процесса, необходимой JavaMail; постоянная
копия на диске зашифрована. DPAPI привязан к профилю пользователя Windows, а не к
переносимому паролю приложения. На других ОС незашифрованного fallback нет.

Свернуть письмо означает сохранить его, удаление вынесено в отдельное действие.
После подтверждённого входа восстанавливаются данные только этого ящика. Восстановление
никогда не отправляет письмо и не возобновляет таймер. Состояния pending/unknown и
SMTP-квитанция блокируют повтор после сбоя; подтверждённый SMTP остаётся read-only.
Если автосохранение не удалось, интерфейс показывает ошибку и сохраняет изменения
в памяти, а закрытие/выход предупреждает о потере последних изменений. Повреждённые
данные не удаляются молча. Single-instance предотвращает параллельные писатели.
Только последняя успешно сохранённая версия переживает аварийное завершение.
Пароль передаётся только локальному процессу. По явной опции «Запомнить аккаунт»
один аккаунт сохраняется через Windows DPAPI CurrentUser. При следующем запуске
вход начинается отдельной кнопкой; пароль не возвращается в JavaScript.
«Забыть сохранённый пароль» удаляет только эту запись, оставляя черновик.
Без выбранной опции новые пароли остаются только в памяти сеанса. Сырые ошибки
и аргументы не выводятся в логи или интерфейс. Запросы и ответы связаны по id,
очередь и размеры ограничены. EOF завершает JVM; оболочка также завершает
дочерний процесс при закрытии окна.

Политики дизайна и поведения: DESIGN.md. Автотесты используют отдельные фикстуры,
не реальные пользовательские данные. Реальное подключение и поведение Windows
нужно проверить до объявления клиента готовым.

Windows-имя установленного приложения — SPbU Mail; интерфейс русский. В manifest
встроенного java.exe добавлен activeCodePage=UTF-8 для путей на кириллице
(Windows 10 1903+ / Windows 11). Остальные настройки manifest сохраняются.
Перед запуском также используется короткий файловый путь, если он доступен.
Локаль Windows и настройки 8.3 не изменяются.


Предварительный Windows-выпуск с календарём: [desktop-v0.1.0-preview.5](https://github.com/nikitasever/spbu-mail-pilot-updates/releases/tag/desktop-v0.1.0-preview.5).

## Календарь CalDAV

Раздел «Календарь» подключает один источник CalDAV для текущего почтового ящика.
Адрес должен быть HTTPS. Логин и пароль календаря вводятся отдельно от почтового
пароля; «Подключить и запомнить» сохраняет их через Windows DPAPI. Можно указать
прямую ссылку на одну коллекцию или обнаружить несколько календарей на сервере
и выбрать нужный. Пароль и закрытые URL коллекций не возвращаются в веб-интерфейс.
Редиректы на другой origin запрещены; переходы внутри того же origin ограничены по числу.

Доступны день, неделя, месяц и повестка. Нажатие на день открывает всплывающий
список со временем, названием, календарём, местом и раскрываемым описанием.
События, повторения и исключения разбирает существующее Java-ядро; время Москвы,
понедельник — первый день недели. Для недели на стыке месяцев загружаются оба.
Календарь работает отдельным транспортом: загрузку можно остановить, почта и
вложения остаются доступны. Поздний ответ не меняет новый период/аккаунт.

События пока доступны только для чтения и хранятся в памяти текущего сеанса.
«Обновить» запрашивает актуальные данные; при ошибке ранее загруженные события
сохраняются с предупреждением. Отсутствие данных не объявляется пустым днём.
«Отключить все календари» удаляет только локально сохранённое подключение,
события сервера не меняются. Создание/редактирование событий и локальные задачи
в эту версию не входят. Протокольные и браузерные проверки используют фикстуры;
подключение к реальному пользовательскому CalDAV-серверу ещё не проверено.


Предварительный Windows-выпуск с контактами: [desktop-v0.1.0-preview.6](https://github.com/nikitasever/spbu-mail-pilot-updates/releases/tag/desktop-v0.1.0-preview.6).

## Контакты СПбГУ

Для активного аккаунта на `mail.spbu.ru` доступны серверная личная книга,
подразделение и общий справочник. «Загрузить», поиск по Enter/«Найти» и алфавит
используют прежний UniversityDirectory; сервер определяет права, книгу и
подразделение. Открытие раздела само не отправляет запросов. Поиск явный, как
в почте: ввод не передаётся до отправки формы; IME не запускает поиск при наборе.
Кнопка очистки отменяет старый поиск и запрашивает начальную страницу.
Доступно явное «Загрузить ещё», не автоматическая выгрузка всего справочника.
Страницы проверяются на повтор курсора; адреса объединяются без дублей, до 5000
контактов в памяти. При устаревшей странице используйте «Загрузить» заново.

Работает отдельный HTTPS-транспорт с отменой и ограничением ответа; пароль
активной почты используется только для фиксированного `https://mail.spbu.ru`,
без редиректов. Ошибка авторизации справочника не отключает IMAP. Нативный слой
связывает запрос с владельцем и сессией; Java проверяет владельца до чтения,
а поздний ответ после смены аккаунта не возвращается в интерфейс.

«Написать» добавляет адрес в текущий редактируемый черновик, сохраняя текст,
файлы и остальных адресатов. Повторный адрес не добавляется. Отправленное письмо
и неизвестный результат отправки не разрешают изменение получателей; кнопка
не создаёт повторную отправку. Контакты не сохраняются на диске и очищаются
при выходе. Изменение серверных книг и серверные книги других провайдеров пока не перенесены. Реальный справочник СПбГУ ещё не проверен:
протокол и браузерные сценарии проверяются на фикстурах.


Предварительный Windows-выпуск с локальной книгой: [desktop-v0.1.0-preview.7](https://github.com/nikitasever/spbu-mail-pilot-updates/releases/tag/desktop-v0.1.0-preview.7).

## Локальная адресная книга

В разделе «Контакты» выберите «На этом компьютере». Для почтовых серверов, кроме
mail.spbu.ru, эта книга выбирается по умолчанию. Можно создать контакт, изменить
имя/почту, удалить с подтверждением и добавить адрес в почтовый черновик. Поиск
и полный алфавит работают по всей локальной книге; «Загрузить ещё» показывает
следующие 50 записей. Предел — 5000 контактов на ящик. Требуется вход в ящик;
это ещё не автономный вход в приложение без IMAP.

Книга сохраняется в app-data/contacts/<owner>/book.dpapi через Windows DPAPI
CurrentUser с контекстом владельца и атомарной заменой. Она привязана к сочетанию
сервер/порт/логин и профилю Windows. Переноса контактов с телефона или синхронизации
с сервером нет. После выхода книга остаётся зашифрованной, а записи и поля формы
очищаются из интерфейса. На других ОС незашифрованного fallback нет.

Каждое изменение проверяет UUID-версию книги и активную сессию. Дубликаты адресов
без учёта регистра отклоняются. Конфликт сохраняет текст формы и блокирует запись
до закрытия/перезагрузки; чужое изменение не затирается. Ошибка чтения/расшифровки
не создаёт новую пустую книгу поверх повреждённой. При ошибке сохранения поля
остаются доступны для исправления или копирования; повтор автоматом не выполняется.
Закрытие изменённой формы требует подтверждения. Обычное закрытие окна учитывает
и контакт, и автосохранение почтового черновика; текущая запись блокирует закрытие
до результата. Внезапное завершение сохраняет только уже подтверждённые изменения:
несохранённая контактная форма не является автоматически сохраняемым черновиком.


Актуальный предварительный Windows-выпуск с импортом: [desktop-v0.1.0-preview.8](https://github.com/nikitasever/spbu-mail-pilot-updates/releases/tag/desktop-v0.1.0-preview.8).

## Импорт CSV / vCard

В локальной книге нажмите «Импорт…» и выберите файл через диалог Windows.
Веб-интерфейс не получает путь и не может читать произвольные файлы. Поддержаны
обычные файлы CSV и VCF до 1 МиБ, до 500 адресов за один импорт; общий предел
книги остаётся 5000. Кодировки: строгий UTF-8 (с BOM или без) и UTF-16 LE/BE с BOM.
ANSI/Windows-1251 автоматически не угадывается: сохраните такой файл в UTF-8.

CSV требует заголовки. Поддержаны Name/Display Name/Full Name/ФИО, Email/E-mail
Address/Почта/Электронная почта, First Name/Last Name или Имя/Фамилия и поля Gmail
E-mail 1 - Value и аналогичные адресные столбцы. Разделители — запятая, точка с
запятой или табуляция; кавычки и удвоенные кавычки разбираются. Пример:

```csv
Name,Email
"Иванов, Иван",ivan@example.org
Петрова Анна,anna@example.org
```

vCard поддерживает текстовые версии 3.0/4.0, переносы длинных строк, FN/N,
экранирование и несколько EMAIL в одной карточке. vCard 2.1 и поля с
quoted-printable/base64 не поддержаны: преобразуйте экспорт в текстовый vCard
3.0/4.0. Параметр CHARSET=UTF-8 разрешён; другие кодировки полей не угадываются.
Телефоны, фотографии, адреса, организации и прочие поля не переносятся и не
загружаются по внешним ссылкам. Импортируются только имя и email; без имени
используется сам адрес.

До подтверждения книга не изменяется. В предпросмотре видны ошибки, уже
существующие адреса и повторы файла; такие строки недоступны для выбора.
Повторы определяются без учёта регистра, первый допустимый адрес файла имеет
приоритет. Можно снять выбор, выбрать доступные записи в пределах свободного
места и импортировать только их. Исходный файл остаётся без изменений.

Нативный предпросмотр хранится только в памяти, связан с владельцем, сессией
и UUID-версией книги. Подтверждение передаёт токен и номера выбранных строк,
не пути или заново сформированные адреса. Весь пакет проверяется до единственной
атомарной DPAPI-записи. Конфликт или ошибка не дают частичного пакета. Успешный
токен погашается; если ответ потерян, повтор в этом предпросмотре заблокирован:
перечитайте книгу и выберите файл заново. Отмена/выход очищает предпросмотр.
Экспорта и синхронизации с телефонной/серверной книгой пока нет.
