# Рабочая почта для Windows — первый прототип

Локальное приложение Tauri 2 с веб-интерфейсом. Отдельный сервер не нужен:
оболочка сама запускает JVM-процесс по stdin/stdout. Java-runtime входит в
установщик. HTTP/TCP-порт для общения частей приложения не открывается.

Первый сценарий: вход по IMAP/TLS, реальный список папок, поиск и пагинация,
чтение по folder/UIDVALIDITY/UID без изменения Seen. Android-код не копируется
в репозиторий: build-engine.py генерирует только две версии исходников с заменой
android.text.Html на настольный HTML-to-text адаптер. Остальные протокольные
классы компилируются из существующего src/. APK на этом этапе не выпускается.

Это не полный перенос APK. Пока нет сохранения аккаунта/пароля на следующий
запуск, офлайн-писем, SMTP/черновиков, открытия вложений, календаря, контактов,
Gemini и системных уведомлений. Вложения показываются только списком имён.
HTML отображается как текст; удалённые изображения не загружаются.

## Проверка разработки

Нужны Node 24, Python 3, полный JDK 17+ и Rust stable. Для локального Tauri на
Windows нужны стандартные Microsoft C++ build tools и WebView2. Это инструменты
разработчика: владельцу установщика Java/Node/Rust/терминал не требуются.

Из корня репозитория:

```sh
python -c "import build; build.dependencies()"
python desktop/tools/test-engine.py
python desktop/tools/build-runtime.py
cd desktop
npm ci
npm test
npm run build
npm run tauri -- dev
```

`npm run dev` отдельно открывает только интерфейс в браузере: там подключение
к почте намеренно недоступно, нет фальшивого успешного входа. `npm run tauri --
build` собирает установщик Windows. Windows-проверка и артефакт настроены в
.github/workflows/desktop-windows.yml. Публичный выпуск не означает проверку
на пользовательском почтовом сервере.

## Безопасность и границы

Команды ограничены capabilities/connect/disconnect/folders/page/body/cancel.
Нет команды произвольного выполнения кода, SMTP или записи файлов из WebView.
Пароль передаётся только локальному процессу и остаётся в памяти сеанса;
после выхода или закрытия приложения нужно подключиться заново. Сырые ошибки
и аргументы не выводятся в логи или интерфейс. Запросы и ответы связаны по id,
очередь и размеры ограничены. EOF завершает JVM; оболочка также завершает
дочерний процесс при закрытии окна.

Политики дизайна и поведения: DESIGN.md. Автотесты используют отдельные фикстуры,
не реальные пользовательские данные. Реальное подключение и поведение Windows
нужно проверить до объявления клиента готовым.

Windows-имя установленного приложения — SPbU Mail; интерфейс русский. В manifest
встроенного java.exe добавлен activeCodePage=UTF-8 для путей на кириллице
(Windows 10 1903+ / Windows 11). Остальные настройки manifest сохраняются.
Перед запуском также используется короткий файловый путь, если он доступен.
Локаль Windows и настройки 8.3 не изменяются.
