# Версия для ПК с веб-интерфейсом

Начало разработки: 28 октября 2026. Готового настольного клиента пока нет.

Исходное требование владельца — локальный запуск без отдельного сервера.
Предварительный вариант: Tauri 2 и локальное JVM-ядро, запускаемое оболочкой.
Уточняется, сохраняется ли это требование или нужна страница обычного браузера.
Веб-интерфейс и почтовое ядро разделяются, чтобы выбор оболочки не потребовал
повторного переноса протокольной логики.

## Проверено в существующем коде

- Готовой папки desktop, Tauri-конфигурации или JVM-sidecar пока нет.
- Старый веб-интерфейс расположен в ui/ и собирается в assets/app.js. Он связан
  с Android-мостом, поэтому открытие HTML в браузере не даёт доступ к почте.
- MailReader.java и MailPreview.java напрямую импортируют android.text.Html.
  До повторного использования на обычной JVM нужна замена именно этого адаптера,
  проверенная на существующих MIME/preview-фикстурах.
- В проверенных MailSender.java, OutgoingMail.java, SavedAccounts.java, CalDav.java
  и MailFolderCatalog.java прямых ссылок на android.* не найдено. Это не доказывает
  переносимость всех их транзитивных зависимостей: их ещё надо скомпилировать
  отдельно от Android и проверить.
- Браузерный JavaScript не подключается напрямую к IMAP/SMTP. Для обычного
  браузера нужен почтовый backend; в настольной оболочке эту роль выполняет
  локальный процесс, не требующий ручного запуска сервера.

## Первый рабочий сценарий

Выбор аккаунта → загрузка реальных папок → входящие с пагинацией → чтение по
account/folder/UIDVALIDITY/UID. Ошибки сети, прогресс, отмена и устаревшие результаты
должны быть видны с первого сценария. Демонстрационные письма не считаются
подключённой почтой. Пароли не попадают в frontend-хранилище или диагностические
логи. Письмо не отправляется без явного действия пользователя.

Android остаётся в своих существующих ветках; APK ради этого этапа не выпускается.
